# 【週次改善提案】2026-07-05

## 今週の要約（3行）

リピッテ・医療CRMの「来院間隔セグメント」概念と、サロンボードの「施術中次回予約」UXから特に具体的なアイデアを着想した。現システムの顧客管理・カウンター・リーダーボードの"次の一手"を埋める5提案。複数院展開という V-ARC 固有の強みを活かしたマルチ院俯瞰ビューも初めて提案する。

---

## 提案① 離脱予兆スコア & 失客アラートバッジ（顧客管理ページ）

**観点:** ②データ分析・経営判断がしやすくなる

### 背景・きっかけ

リピッテ（LINE予約SaaS）は「最終来店から60日経過した顧客に自動メッセージ」を送るセグメント機能でリピート率9割超を実現している（参照: https://xs393208.xsrv.jp/repitte/ ）。医療CRM向けガイドでも「来院周期からズレ始めている"流出可能性患者"を自動抽出し、フォローを行う」ことが失客防止の要として挙げられている（参照: https://march-cos.com/2025/06/26/clinic-crm-guide/ ）。現システムの顧客管理（`src/app/admin/customers/`）は患者一覧の表示・検索はできるが、来院間隔の「ずれ」を自動検出してスタッフに見せる仕組みは存在しない。

### 提案内容

顧客管理ページの患者一覧に **「要フォロー」バッジ** を追加する。ロジックは「直近の来院日から計算した平均来院間隔の1.5倍以上、来院がない患者」を自動抽出（例: 週1来院の患者が3週以上空いたら黄色バッジ、2倍以上で赤バッジ）。

- 患者行の横に `🟡 要注意` / `🔴 要フォロー` バッジを表示
- バッジでフィルタリングできる「フォロー待ち表示」トグル
- 「フォロー待ち全員にLINE送信」ボタン → 既存の LINE キャンペーン（`sendSegmentedCampaign`）のターゲットとして連携

受付スタッフが毎朝「今日フォローすべき患者」を一目で把握でき、院長がLINE配信ターゲットを迷わず選べるようになる。

### 期待できる効果

- 失客の"前兆"を見逃さずにフォローでき、リピーター維持率が向上
- LINE配信のターゲット精度が上がり、「とりあえず全員送信」から脱却できる

### 実装イメージ

- `src/app/actions/adminCustomers.ts` の `getCustomers()` に来院間隔計算ロジックを追加（Supabase上の`appointments`テーブルから最終来院日・来院頻度を集計）
- `src/app/admin/customers/CustomersTable.tsx` にバッジ列を追加
- `src/app/admin/marketing/page.tsx` の `sendSegmentedCampaign` 呼び出しに「フォロー待ち」セグメントを追加
- **難易度: 中**（Supabaseクエリと表示改修。LINEキャンペーン連携で+1段階）

### 優先度: **高**

毎日の受付業務と週次のLINE配信の両方に直結する。患者が自然に離れていくのを防ぐ、最も ROI の高い施策と判断。

## 提案② 施術完了時「次回予約ワンタップ」ダイアログ（受付カウンター）

**観点:** ①利用者（受付・院長）が使いやすくなる

### 背景・きっかけ

ホットペッパービューティー/サロンボードは「施術中にスタッフが次回予約を入れる」機能を強みとしており、来店中に次回を確定させることでリピート率を高めている（参照: https://selfregister.net/hot-pepper-pos/ ）。海外では SimplyBook.me が「施術後に次回予約リンクをその場で渡す」フローを推奨している（参照: https://simplybook.me/ja/booking-system-features ）。現システムの受付カウンター（`src/app/admin/counter/page.tsx`）には「来院完了」ボタンがあるが、完了後に次回予約を促す仕組みが存在しない。

### 提案内容

**受付カウンターの「来院完了」ボタンを押した直後に、小さなモーダルを表示する。**

```
✅ 〇〇さんの来院を完了しました。
─────────────────────────
📅 次回予約を今すぐ入れますか？
  [日付ピッカー]  [時間ピッカー]
  [スタッフ]  [メニュー]
  
  [次回予約を入れる]  [スキップ]
```

- 患者の前回コースを初期値としてプリセット（変更可能）
- 「次回予約を入れる」を押せば即座に予約が入り、患者の LINE に確認メッセージが飛ぶ
- 「スキップ」を押せばこれまで通りの動作

受付スタッフが「次の予約いつにしますか？」と口頭で確認しなくても、画面を見せながら自然にセットできる。

### 期待できる効果

- 帰り際の「また来てください」が「次回の予約確定」に変わり、リピート率が大幅向上
- スタッフが口頭で次回を案内する心理的ハードル（特に新人）が下がる

### 実装イメージ

- `src/app/admin/counter/page.tsx` の「来院完了」処理後にモーダル表示
- `src/app/actions/adminReserve.ts` の既存 `updateCheckinStatus` と `AddAppointmentDialog` コンポーネントを流用・拡張
- **難易度: 小〜中**（既存の予約追加ダイアログ `AddAppointmentDialog` を `completeAndRebook` モードとして呼び出すだけでほぼ完成できる）

### 優先度: **高**

実装コストが低く、毎日何十回も発生する「来院完了」操作に乗っかるため、効果が即日出る。

## 提案③ スタッフ個人 KPI 進捗マイページ（担当別売上・来院数の見える化）

**観点:** ③スタッフ管理がしやすく、スタッフのモチベーションが上がる

### 背景・きっかけ

接骨院経営のKPI活用事例では「スタッフは何をすべきかが明確になり、挙げるべき成果の目安を理解できる」ことでモチベーションが向上するとされている（参照: https://www.hone-u.com/column/cate6b1zb/notefi1zb.php ）。サロンボードは「スタッフ別・メニュー別に売上を集計・出力できる」機能を提供し、スタッフが自分の実績を把握できるようにしている（参照: https://selfregister.net/hot-pepper-pos/ ）。現システムのリーダーボード（`src/app/admin/leaderboard/page.tsx`）はポイント（アクション回数ベース）のみで、「自分が今月何人の患者を担当し、売上にどれだけ貢献したか」がスタッフから見えない。

### 提案内容

**`/admin/my-schedule` または新規 `/admin/my-stats` ページに「今月の自分の実績サマリー」ブロックを追加する。**

表示内容（ログインスタッフの担当データのみ）:

| 指標 | 例 |
|---|---|
| 今月の担当来院数 | 87人 / 目標100人（進捗バー 87%） |
| 担当売上（自費） | ¥412,000 |
| 担当患者のリピーター率 | 72% |
| リーダーボード順位 | 🥇 1位（324pt） |
| 今月の初診対応数 | 8人 |

- 院長は院全体の目標を設定し、スタッフはその院全体目標に対する自分の貢献割合を確認
- 進捗バーで「目標まであと○人」を視覚化

### 期待できる効果

- スタッフが自分の貢献をリアルタイムで確認でき、自律的に行動するようになる
- 院長が「○○さん今月担当少ないね」と個別に声がけするための根拠データになる
- 現リーダーボードのポイントに「実績の深み」が加わり、ゲーミフィケーション効果が増す

### 実装イメージ

- `src/app/actions/analytics.ts` に `getMyStaffStats(staffId, year, month)` を追加（予約・売上テーブルを `staff_id` で絞り込む）
- `src/app/admin/my-schedule/page.tsx` にサマリーカードブロックを追加、または新ページ作成
- 目標値は `src/app/admin/evaluation/page.tsx` の院全体目標から比例計算
- **難易度: 中**（Supabaseクエリ拡張 + UI実装。目標設定のスタッフ個別化まで踏み込むと大）

### 優先度: **中〜高**

スタッフのモチベーション施策は中長期の院経営安定に効く。実装コスト中・効果大の黄金比。

## 提案④ 複数院横断 KPI 俯瞰ビュー（マルチクリニック ダッシュボード）

**観点:** ②データ分析・経営判断がしやすくなる

### 背景・きっかけ

Salesforce Healthcare Cloud やエンタープライズ系医療CRMは「複数拠点のKPIを一画面で横比較する」機能を経営者向けの核心機能として位置づけている（参照: https://www.salesforce.com/jp/solutions/industries/healthcare/providers/ ）。現システムはボール・からだ・マッスル・RELAQ という複数院で共用されているが、院長が全院のパフォーマンスを比べるには、毎回院を切り替えてログインし直す必要がある。現在の経営評価（`/admin/evaluation`）と分析（`/admin/analytics`）はどちらも単一院のデータのみを表示している。

### 提案内容

**新規ページ `/admin/clinics-overview`（全院俯瞰ビュー）を院長権限のみに追加する。**

```
┌──────────────────────────────────────────────┐
│  📊 全院パフォーマンス比較  ─ 2026年7月       │
├──────────┬──────────┬──────────┬─────────────┤
│ ボール   │ からだ   │ マッスル │ RELAQ       │
│ ───────  │ ───────  │ ───────  │ ─────────── │
│ 来院 182 │ 来院 241 │ 来院 98  │ 来院 167    │
│ 売上 ¥87万│ 売上¥121万│ 売上¥44万│ 売上¥83万   │
│ 新規  14 │ 新規  22 │ 新規  8  │ 新規  19    │
│ リピ 79% │ リピ 82% │ リピ 75% │ リピ 81%    │
│ スコア78 │ スコア85 │ スコア62 │ スコア80    │
└──────────┴──────────┴──────────┴─────────────┘
  [今月] [先月] [前年同月比]
```

- 全院の売上グラフを1本に重ねた比較折れ線グラフ
- 最下位の院に「⚠️ 来院数が平均より30%下」のアラートバッジ
- 各院カードをクリックするとその院の詳細分析ページへジャンプ

### 期待できる効果

- 院長がどの院に注力すべきかを即座に判断できる（週次経営会議でそのまま使える）
- 「A院は好調だがB院がこの1ヶ月で急に落ちた」などの異変を早期検知
- 全体を見渡すビューがあることで、院間の良い取り組みを横展開しやすくなる

### 実装イメージ

- `src/app/actions/analytics.ts` に `getAllClinicsKpi(year, month)` を追加（全clinic_idを取得し並列クエリ）
- 新規 `src/app/admin/clinics-overview/page.tsx` を作成、院長ロール権限チェック付き
- `onboarding/` の clinic_id 一覧を参照してクリニック名をマッピング
- **難易度: 中**（Supabaseの横断クエリ設計とUI実装。権限管理がある分+α）

### 優先度: **中**

複数院を抱えるぼーるくんにとって固有価値が高い機能。ただし今すぐ困っているわけではなく、成長フェーズ向けの施策。

## 提案⑤ 待合室リアルタイム表示 URL（デジタルサイネージ対応）

**観点:** ①利用者（受付・院長）が使いやすくなる

### 背景・きっかけ

医療機関向けデジタルサイネージの調査で「待合室に番号案内システムを導入することで患者の不満（いつ呼ばれるかわからない不安）が減少し、スタッフへの口頭問い合わせが激減する」事例が増加している（参照: https://panelize.jp/blogs/column/hospital-digital-signage-guide ）。接骨院DXの文脈でも待合室体験の改善が注目されている（参照: https://kartte.jp/column/6913de00db6a3b0644f0123d ）。現在のキャンセル待ち管理（`src/app/admin/waitlist/page.tsx`）と受付カウンター（counter）の情報は管理画面内にしかなく、患者が待合室で自分の順番を確認する術がない。

### 提案内容

**認証不要の専用 URL `/display/[clinic_id]`（大画面向け）を新設する。**

表示内容（自動更新 30秒ごと）:

```
┌──────────────────────────────────────┐
│  🏥 ボール接骨院 – 本日の待ち状況     │
│                                      │
│  🔔 現在ご案内中:  山田 様           │
│                                      │
│  ⏳ お待ちの方: 3名                  │
│                                      │
│  ────────────────────────────────   │
│  次のご予約: 10:30 ／ 11:00 ／ 11:30 │
│                                      │
│  📢 本日の待ち時間目安: 約15分        │
└──────────────────────────────────────┘
```

- 院のタブレットやテレビに表示させるだけで即運用開始
- 「現在案内中の患者名」は受付カウンターで「呼び出し中」にした患者を表示（個人名は敬称のみ or イニシャルも選択可）
- 認証なし・読み取り専用・トークン付きURLでセキュリティ確保

### 期待できる効果

- 「あと何人待ちですか？」という受付への口頭問い合わせが激減し、スタッフの集中力が増す
- 患者の待ち時間不安が下がり、Google口コミ評価の向上にもつながる
- タブレット1台で実現できる低コストの患者体験向上策

### 実装イメージ

- 新規 `src/app/display/[clinic_id]/page.tsx`（Server Component + 定期 revalidate または Supabase Realtime）
- `src/app/actions/adminReserve.ts` の待ち状況データを利用
- URLには time-limited token（`publicSettings`テーブルに発行・管理）
- **難易度: 小〜中**（認証バイパスのルート設計が主な考慮点。表示自体はシンプル）

### 優先度: **中**

スタッフ負荷軽減と患者満足度向上の2つに効く。特に多忙な時間帯に効果を発揮する施策。
