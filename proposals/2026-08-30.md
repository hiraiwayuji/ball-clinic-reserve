### 提案①：キャンセル待ち「自動繰り上げLINE通知」

**観点：** ①利用者（受付・院長）が使いやすくなる

**背景・きっかけ**

Square Appointments・SimplyBook.me ��比較レポート（[Zapier 2026 Best Scheduling Apps](https://zapier.com/blog/best-appointment-scheduling-apps/)）では、ウェイトリストへの「自動空き枠通知」が標準機能として当たり前になっている。現在の V-ARC のキャンセル待ち管理（`src/app/admin/waitlist/page.tsx`）は、受付スタッフが手動で確認→電話という運用であり、スタッフが施術中や休憩中だと繰り上げに気づかない。

**提案内容**

予約がキャンセルされた瞬間（`appointments.status` が `cancelled` に変わった時点）に、Supabase の DB Webhook もしくは既存の `manage-reservation` server action のキャンセル処理末尾に以下フローを追加する：

1. 同一日時・同一コースのキャンセル待ちエントリを `position` 順に取得
2. 1位の患者に LINE で「〇月〇日〇時のご予約に空きが出ました。15分以内にご返信ください」を自動送信
3. 15分以内に返信がなければ2位へ送信（タイムアウト処理）
4. 管理画面ウェイトリストページに「通知済み・応答待ち・繰り上げ確定」のステータスを追加表示

受付スタッフは何もしなくてよい。繰り上げが確定したら通知が来るだけ。

**期待できる効果**

- 空き枠の無駄ゼロ化（現状、繰り上げに30分〜1時間かかることも）
- スタッフの電話業務削減・施術集中時間の確保
- 患者満足度向上（「すぐ連絡が来る院」）

**実装イメージ**

- 既存ファイル：`src/app/actions/manage-reservation.ts`（キャンセル処理に追記）、`src/app/admin/waitlist/page.tsx`（ステータス表示追加）
- 新規：`src/app/actions/waitlist-notify.ts`（LINE通知ロジック）、Supabase Edge Function or cron for timeout
- 既存の LINE 送信基盤（`src/app/actions/line-marketing.ts`）を流用できる
- **難易度：中**（LINEは送信済み、ウェイトリストDBも存在、「自動トリガー」部分のみ新規）

**優先度：高**
スタッフ業務に直接効く即効性があり、既存コードの再利用度が高い。患者体験の改善効果も大きい。

### 提案②：顧客一覧「久しぶり離脱リスクバッジ」

**観点：** ②データ分析・経営判断がしやすくなる

**背景・きっかけ**

「顧客維持率を5%改善するだけで利益が25〜95%向上する」というLTV研究（[GBase Support ブログ 2026](https://cs.gbase.ai/blog/ltv-customer-lifetime-value-guide/)）が示す通り、離脱防止は新規獲得より費用対効果が高い。V-ARC のAI秘書（`src/app/actions/ai-secretary-multi.ts` 322行目）には「直近14日に3回連続キャンセル＝離脱兆候」の検知ロジックがあるが、これは毎朝のブリーフィングの中に埋もれており、能動的に確認しない限り見逃す。

チャーン予測AIの比較記事（[koromo.io 2026](https://koromo.io/blog/customer-churn-prediction-ai/)）では「最終来院からの経過日数 × 平均来院頻度 × 過去キャンセル率」の組み合わせが最もシンプルで精度の高い離脱シグナルとされている。

**提案内容**

顧客一覧ページ（`src/app/admin/customers/CustomersTable.tsx`）の各行に「久しぶり度」バッジを追加する：

- **赤バッジ「要フォロー」**：平均来院間隔の2倍以上が経過 かつ 過去3ヶ月来院ゼロ
- **黄バッジ「要注意」**：平均来院間隔の1.5倍超
- **（緑バッジなし）**：通常患者は何も表示しない（ノイズ排除）

さらに顧客詳細の画面上部に「最終来院: ○日前 / 平均○日ごとに来院 / キャンセル率○%」の3行サマリーを追加。
赤バッジ患者を一括選択して「フォローLINEを送る」ボタンを1タップ（既存のセグメント配信を活用）。

**期待できる効果**

- 院長・受付が毎朝一覧を見るだけで離脱しそうな患者を把握できる
- LINEフォロー送信まで2クリックで完結、抜け漏れなし
- リピート率・来院頻度指標の改善

**実装イメージ**

- `src/app/actions/adminCustomers.ts` に `avgIntervalDays`, `daysSinceLastVisit`, `churnRiskLevel` フィールドを追加（Supabase の appointments テーブルから集計）
- `src/app/admin/customers/CustomersTable.tsx` にバッジ列追加
- **難易度：小〜中**（DB集計は既存パターンの延長、UIはバッジ1列追加のみ）

**優先度：高**
実装コスト小・経営インパクト大の組み合わせ。AI秘書の既存ロジックを可視化するだけなので「新発明」ではなく「現出」。

### 提案③：複数院「クロス比較ダッシュボード」

**観点：** ②データ分析・経営判断がしやすくなる

**背景・きっかけ**

日本の接骨院チェーン向けシステム COCKPIT（[治療院HUB 比較記事](https://www.chiryoin-hub.com/blog/osteopathic-clinic-reservation-system)）が「数値分析＋コンサルAIアドバイス機能」を売りにしているように、多院展開院の経営者が最も欲しいのは「各院を並べて見たとき、どこが伸びていてどこが落ちているか」の一覧性。現在の V-ARC のアナリティクス（`src/app/admin/analytics/page.tsx`）は単一院での期間比較のみで、院をまたいだ比較ビューがない。

**提案内容**

新規ページ `/admin/analytics/cross-clinic` を作成し、ぼーるくんが管理する4院（ボール接骨院・からだ・マッスル・RELAQ）を横に並べた比較テーブルを表示する：

| 指標 | ボール接骨院 | からだ | マッスル | RELAQ | 全体平均 |
|------|------------|-------|---------|-------|----------|
| 当月売上 | ¥XXX | ¥XXX | ¥XXX | ¥XXX | ¥XXX |
| 来院数 | XX人 | XX人 | XX人 | XX人 | XX人 |
| 新規比率 | XX% | → | → | → | → |
| キャンセル率 | XX% | → | → | → | → |
| リピート率 | XX% | → | → | → | → |

各指標は全院平均より良い場合に緑、悪い場合に赤でハイライト。月を選択して比較可能。
AI秘書コメントを「全院まとめ版」で1つ生成（「今月はからだ院の新規比率が全院トップ。施策を他院に横展開を検討してください」のようなサジェスト）。

**期待できる効果**

- 月次経営MTGの資料作成ゼロ化（このページを見るだけで議論できる）
- 院ごとの強み���弱みの即時把握
- スタッフへのフィードバック材料になる

**実装イメージ**

- `src/app/actions/analytics.ts` に「全clinic_idを横断して集計するクロス比較関数」を追加
- `src/app/admin/analytics/` 配下に `cross-clinic/page.tsx` を新規作成
- AI秘書の既存 `generateAnalyticsComment` を「multi-clinic用プロンプト」に拡張
- **難易度：中**（既存analyticsロジックの多clinic対応が主な作業）

**優先度：中**
経営判断ツールとして価値が高いが、毎日使うものではなく月1〜2回。ただし「ぼーるくんが使うほぼ唯一の多院管理機能」なので中期的に必須。

### 提案④：リーダーボード「バッジ＋月次チームチャレンジ」

**観点：** ③スタッフ管理がしやすく、スタッフのモチベーションが上がる

**背景・きっかけ**

Frontiers in Psychology 2025年論文（[Gamified HRM and Employee Engagement](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2025.1746973/full)）では、「ゲーミフィケーションは仕事への関与を有意に高めるが、順位だけ見せる単純なランキングは若い世代のストレスを増やす」と指摘。Bucketlist Rewards 2026ガイド（[Gamification Employee Engagement Strategies](https://bucketlistrewards.com/blog/gamification-employee-engagement-strategies-tools/)）は「**複数の達成ルート**（チームチャレンジ・個人マイルストーン・ピア承認）を用意すると内発的動機が上がる」と勧めている。

現在の V-ARC リーダーボード（`src/app/admin/leaderboard/page.tsx`）は「総合ポイントの順位表示」のみで、「底辺スタッフが見たくなくなる」課題がある。

**提案内容**

リーダーボードページを3タブ構成に拡張する：

**タブ1「ランキング」**（現状維持）

**タブ2「バッジウォール」**
自動付与される実績バッジを表示（自分と他者の両方）：
- 「連続記帳王」：7日連続で売上記帳
- 「新規患者マスター」：今月の新規対応5件以上
- 「ゼロノーショー」：今月無断キャンセル対応ゼロ
- 「シフト完走」：今月欠勤・遅刻ゼロ
- 「フォローマスター」：今��のLINE配信を3回実施
バッジは全員が条件を満たせば全員もらえる（ゼロサムにしない）

**タブ3「今月のチームチャレンジ」**
院長が月初に「今月の全院目標」を設��できるフォームを追加：
- 例：「今月の全院新規患者数 100人達成」「全スタッフがブログを1記事投稿」
- 進捗バーを全スタッフが見られる（院を超えた協力感の醸成）

**期待できる効果**

- 下位スタッフが「バッジは自分も取れる」ため離脱感を感じない
- チームチャレンジで院を超えた連帯感が生まれる
- 院長が個別承認コメントを残せる

**実装イメージ**

- Supabase に `staff_badges` テーブルを追加（badge_type, user_id, earned_at）
- `src/app/actions/security.ts`（ポイント計算ロジックあり）にバッジ付与ロジックを追加
- `src/app/admin/leaderboard/page.tsx` にタブUI追加
- **難易度：中**（バッジ計算ロジックは既存ポイントロジックの亜種）

**優先度：中**
現状のリーダーボ���ドを「使ってもらえるもの」にアップグレードする施策。コスト低め・効果は長期で出る。

### 提案⑤：来院前「症状セルフチェックLINE」（当日朝の自動配信）

**観点：** ①利用者（受付・院長）が使いやすくなる

**背景・きっかけ**

整骨院の予約システム比較記事（[digi-mado.jp 2026年版](https://digi-mado.jp/category/business/treatment-center-booking-system/)）では「来院前デジタル問診機能」が付加価値として挙げられ始めている。AI患者スケジューリングガイド（[Prosper AI 2026](https://www.getprosper.ai/blog/ai-patient-scheduling-guide)）では「予約前にAIが症状・部位・強度を収集しておくことで施術者の初動準備が速くなる」とある。

V-ARC には既に新患向け「ウェルカム問診票」（`sendWelcomeQuestionnaire` in `line-marketing.ts`）があるが、**毎回来院前に「今日はどこが不調ですか？」と聞く機能がない**。受付スタッフが「今日の症状を紙に書いてもらう」「口頭で聞いて伝達する」手間は毎日発生している。

**提案内容**

予約日当日の朝8時（設定可変）に、その日に予約がある患者に LINE で以下を自動送信する：

```
【ボール接骨院】本日〇時のご予約ありがとうございます。
来院前に今日の状態を教えてください
▶ 今日はどこが一番つらいですか？
  1. 首・肩
  2. 腰・背中
  3. 膝・股関節
  4. 手・腕
  5. その他
数字で返信してください。施術者が事前に準備します。
```

患者が返信した内容は、予約詳細画面（`src/app/admin/appointments/page.tsx` と施術者のスケジュール）に「今日の訴え：腰・背中」として自動付記される。
返信なしの場合はスルー（強制しない）。

施術者は来院前にスマホで「今日の担当患者一覧→各自の今日の訴え」を1画面で確認できる。

**期待できる効果**

- 受付での問診票記入・口頭確認が不要になる（1患者あたり2〜3分短縮）
- 施術者が患者来院前にメンタルモデルを作れる（施術品質の向上）
- 患者に「気にかけてもらっている」感を与えリピート率向上
- 施術後の「どう変わったか」を次回の前回訴えと比較できるようになる（カルテ補強）

**実装イメージ**

- `src/app/actions/reminders.ts` に「当日問診メッセージ送信」関数を追加（既存リマインダーロジックを参考に）
- LINE webhook で患者からの返信を受け取り、`appointment_symptom_checkin` テーブルへ保存
- `src/app/admin/appointments/page.tsx` で当日予約一覧に「訴え」カラムを追加表示
- `src/app/admin/settings/page.tsx` で「送信時刻・選択肢テキスト」を院ごとに設定可能に
- **難易度：中〜大**（LINE Webhook の双方向処理が新規。送信だけなら小）

**優先度：中**
受付スタッフの体験が最も劇的に変わる機能だが、LINE双方向処理の実装コストがやや高い。まず「送信だけ・返信は自由テキス��」のMVPから始めると良い。
