# V-ARC 週次改善提案 — 2026-09-27

## 今週の要約（3行）

「来院が止まりそうな患者を事前に察知してLINEで引き戻す」「キャンセル待ちをリアルタイムに自動通知する」「スタッフが月次KPIを自分で持てる仕組みを作る」——この3軸が今週のコアテーマです。いずれも国内外の競合サービスで既に標準機能になっているが、V-ARCにはまだなく、実装インパクトが高い。今週の外部リサーチでは「来院間隔アラートによるCRM自動フォロー」がリピート率を9%→30%に引き上げた事例を確認できたため、提案①を最優先と判断しました。

---

## 提案 ① 離脱予兆アラート一覧 ＋ ワンタップLINEフォロー

**観点：** ① 使いやすさ / ② 経営判断

**背景・きっかけ**
整骨院向けCRM各社（Lステップ / アーキライズワークス社ブログ）が「来院間隔でチャーン予兆を検知し自動メール・LINEで呼び戻せる」機能を訴求。国内事例ではLINE予約＋ステップ配信でリピート率が9%→30%に改善した報告が複数確認された。
参照URL: https://note.com/alive_nerine9437/n/ndbfc1fe0c0d0 / https://www.archrise-works.com/blog/webmarketing/整骨院向けcrmとは

**提案内容**
- 管理画面「顧客管理」または「販促」に「離脱予兆リスト」タブを新設
- DBで「最終来院日から◯日以上経過 & 過去3ヶ月に2回以上来院あり」の顧客を自動抽出
- リスト上でチェックをつけて「まとめてLINE送信」ボタンを押すと、既存の LINE 配信機能(line-marketing.ts)経由で「お久しぶりです。お体の調子はいかがですか？」テンプレートメッセージを送れる
- アラート閾値（28日 / 45日 / 60日）は院ごとに設定画面から変更可能
- 院長ダッシュボードのサマリカードに「今月の予兆患者: ○人」と表示

**期待できる効果**
- 退院した患者の呼び戻し、リピート率の継続的改善
- 受付が「誰に声かけするか」を考える必要がなくなり業務が標準化される

**実装イメージ**
- `src/app/actions/adminCustomers.ts` に `getLapsedPatients(clinicId, thresholdDays)` を追加（Supabase クエリ）
- `src/app/admin/marketing/page.tsx` or 新規 `src/app/admin/marketing/lapsed/page.tsx`
- `src/app/actions/line-marketing.ts` の `sendSegmentedCampaign` に顧客IDリスト渡しを追加
- 難易度: **中**（既存LINE送信基盤を再利用）

**優先度: 高**
リピート率改善は収益に直結。既存のLINE送信インフラ(line-marketing.ts)があるため追加実装範囲が限定的で費用対効果が非常に高い。

## 提案 ② キャンセル待ち自動LINE通知（Fresha 式インテリジェントウェイティング）

**観点：** ① 使いやすさ

**背景・きっかけ**
Fresha（グローバルNo.1サロン予約SaaS）には「Intelligent Waitlist」機能があり、キャンセルが出た瞬間にウェイティングリスト上の顧客へLINE等の通知を自動発火。「先着1名が取れる」「高LTV顧客を優先」「全員に一斉案内」の3モードを選択可能。V-ARCにはwaitlist.tsxがあるが、キャンセル発生→自動通知の経路がなく、受付が手動で連絡している。
参照URL: https://www.fresha.com/help-center/knowledge-base/calendar/169-send-waitlist-updates / https://squareup.com/help/us/en/article/7923-waitlist-with-square-appointments

**提案内容**
- 予約のステータスが「キャンセル」に変わった際（`adminReserve.ts` の `updateCheckinStatus` or 予約削除トリガー）にウェイティングリストをチェック
- 同じ日時に並んでいる順番1位（または全員）にLINEプッシュ通知「○月○日 ○時の枠が空きました。予約はこちら→」を自動送信
- 管理画面 `waitlist/page.tsx` に通知モード選択（先着 / 優先 / 全員）を追加
- 30分以内に誰も予約しなければ次の候補へ繰り下げ通知

**期待できる効果**
- 直前キャンセルによる売上損失の最小化
- 受付スタッフが手動で電話連絡する手間を削減（1件あたり5〜10分の削減見込み）

**実装イメージ**
- `src/app/actions/adminReserve.ts` の予約キャンセル処理に `notifyWaitlistOnCancel()` を追加
- `src/app/actions/reminders.ts` や LINE Push API をラップした既存機能を流用
- `src/app/admin/waitlist/page.tsx` に通知設定UI追加
- Supabase リアルタイム or DB トリガーで発火
- 難易度: **中**（Supabaseトリガー設計が必要だが、LINE送信基盤は流用可）

**優先度: 高**
受付負荷軽減＋売上損失防止の両面で即効性あり。

## 提案 ③ 顧客コホート分析（来院回数別 継続率 × LTV チャート）

**観点：** ② 経営判断

**背景・きっかけ**
STORES が2025年3月に発表した「美容サロン顧客データ活用実態調査」で、高成長店は「リピート顧客率」「顧客単価」「物販売上」をコホート単位で追う傾向にあることが示された。美容室の研究では来院回数3回目に大きな離脱の壁があることが多く、どのフェーズで定着するかを可視化する経営的価値は高い。V-ARCの分析画面には月次比較・曜日別・訪問者属性比較があるが、「来院回数別コホート」は未実装。
参照URL: https://www.st.inc/news/2025-03-18-reserve-research-salon / https://local-mp.co.jp/media/columns/btoc-salon-repeat-strategy/

**提案内容**
- `src/app/admin/analytics/page.tsx` に「コホート分析」タブを追加
- 顧客を「1回来院」「2〜3回」「4〜6回」「7回以上」の4バンドに分類
- 各バンドの指標を表示:
  - **離脱率**: バンドに入って次の来院なく90日経過した割合
  - **平均来院間隔（日）**
  - **平均LTV（来院1回あたり売上×平均来院回数）**
  - **バンド人数・構成比** （棒グラフ+パーセント）
- 期間フィルタ（過去3ヶ月 / 半年 / 1年）で切替可能
- 「3回目の離脱が多い院は、2回目来院後の自動フォローを強化しましょう」という AI コメントを下部に表示（`generateAnalyticsComment` を活用）

**期待できる効果**
- 「何回目に患者が離れやすいか」が数値で把握でき、ピンポイントでフォロー施策（提案①と連携）できる
- 競合院との差別化ポイント（経営数値をここまで深掘りできるSaaSは少ない）

**実装イメージ**
- `src/app/actions/analytics.ts` に `getCohortAnalysis(clinicId, months)` 関数追加
- `src/app/admin/analytics/page.tsx` に新タブ追加
- recharts の `ComposedChart` + `Bar` で可視化
- 難易度: **中**（SQL集計が複雑なため、CTEで計算ロジックを組む必要あり）

**優先度: 中**
院長にとって「経営の解像度が上がる」体験を提供でき、SaaSとしての差別化にもなる。即売上に直結するわけではないが意思決定品質が上がる。

## 提案 ④ 施術後ステップ配信スケジューラー（ファーストフォロー自動化）

**観点：** ① 使いやすさ

**背景・きっかけ**
Lステップ・Salon Brain など治療院向けLINEマーケツールで「施術後シナリオ配信」が急伸中。初回来院の翌日「お身体の調子はいかがですか」、3日後「セルフケア動画はこちら」、7日後「次回ご予約はこちら」のように時系列で自動フォローする仕組みで、再来院率が25%→65%に改善した事例がある。V-ARCの現在のLINE配信は「今すぐ送る」一斉配信がメインで、患者ごとの来院タイミング起点のステップ配信がない。
参照URL: https://salonbrain.co.jp/columns/260612/ / https://lflow.net/column/line-sekkotsuin-marketing/

**提案内容**
- 管理画面「LINE・販促」に「ステップ配信シナリオ」サブページを新設
- 院長がシナリオを作成: 「来院後○日後」「テキスト or LINEリッチメッセージ」を複数ステップ登録
- トリガー: 特定のメニュー（例：初回来院 / 自費コース）で予約が完了したとき自動起動
- Supabase の cron job（pg_cron）or Next.js Route Handler + Vercel Cron で毎日処理バッチを回し、「送信日 = 今日」になったメッセージをLINE Push
- 既存の `line-marketing.ts` LINE Push基盤を再利用

**期待できる効果**
- 受付スタッフが何もしなくても自動で患者フォローが走り、再来院率が継続的に向上
- 院によってシナリオをカスタマイズ可能（ボール接骨院とRELAQで別シナリオ設定）

**実装イメージ**
- `src/app/admin/marketing/step-messages/` ページ（新規）
- DB: `step_message_scenarios` テーブル(シナリオ定義) + `step_message_queue` テーブル(患者ごとの予定)
- `src/app/actions/line-marketing.ts` に `processStepMessageQueue()` を追加
- 難易度: **大**（DBスキーマ設計＋バッチ処理の追加が必要）

**優先度: 中**
効果が大きく将来的な核機能になりうるが、実装規模が大きいため段階的アプローチ（まずシナリオ1本のみ対応）を推奨。

## 提案 ⑤ スタッフ個人月次KPI設定 ＋ 院長フィードバックコメント機能

**観点：** ③ スタッフ管理・モチベーション

**背景・きっかけ**
Co:TEAM など医療・整骨院に導入実績のあるOKRツールが「目標/評価/1on1/称賛フィードバックを一元管理」することで組織への帰属意識を高める効果を訴求。一方、V-ARCのリーダーボードは現状「累積アクション数のランキング」であり、個人が「自分の月の目標」を持つ機能がない。毎月コミット→進捗確認→院長からの一言フィードバック、の小サイクルを回せる仕組みを追加することで、スタッフのモチベーション維持と離職率低下に貢献できる。
参照URL: https://www.hrbrain.jp/media/evaluation/okr / https://www.senq-web.jp/how-to/blog/how-to-use-gamification

**提案内容**
- `src/app/admin/leaderboard/page.tsx` またはスタッフ専用マイページに「今月の目標」セクションを追加
- スタッフが月初に「予約対応件数 ○件」「売上貢献 ¥○○,000」などを数値入力
- 月中の実績（既存の `getLeaderboard()` から取得可能）と対比した達成率をプログレスバーで表示
- 院長ロールのみ「フィードバック一言コメント」を残せる入力欄 → スタッフが自分のページで閲覧可能
- 月末に「目標達成できました！」バッジが自動付与されリーダーボードに★マークが付く

**期待できる効果**
- スタッフが「数字と向き合う習慣」がつき、主体的な貢献意識が生まれる
- 院長がスタッフ1人1人へフィードバックする仕組みが手軽に整い、1on1の代替/補完になる
- 離職率の低下（日常的に承認を受けられる環境づくり）

**実装イメージ**
- DB: `staff_monthly_goals` テーブル(目標値/コメント)
- `src/app/actions/security.ts` (getLeaderboard) に個人目標の達成率計算を追加 or 新 action
- `src/app/admin/leaderboard/page.tsx` に入力UI・進捗バー・コメントセクション追加
- 難易度: **小〜中**（UI追加＋テーブル1枚追加で実装可能）

**優先度: 中**
実装コストが低い割にスタッフ満足度への効果が大きい。リーダーボードはすでにあるので、その拡張として自然にフィットする。
