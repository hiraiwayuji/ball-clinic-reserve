# 【週次提案】2026-11-08 V-ARC 改善アイデア

---

## 今週の要約（3行）

外部の接骨院・サロン向けCRM事例と、Freshaなど海外先行SaaSの機能を比較調査した。  
今週は「離脱を防ぐ」「口コミを増やす」「収益着地を先読みする」「スタッフのやりがいを高める」「シフト間の情報ロスをなくす」の5点を提案する。  
3件は既存コードの小改修で着手でき、今月内のリリースを目指せる。

---

## 提案 1：来院途絶えアラート「リスク患者ウィジェット」をダッシュボードに追加

**観点**: ①利用者（受付・院長）が使いやすくなる / ②データ分析・経営判断がしやすくなる

### 背景・きっかけ
電子カルテ・CRM活用の実践記事（clius.jp）で「来院が止まった患者を電子カルテデータで早期発見する方法」が紹介されており、**「前回来院から30日経過 ＋ 次回予約なし」を自動検知して再来院アクションにつなぐ設計**が業界標準になりつつある。  
参照: https://clius.jp/mag/2026/04/23/stop-coming-patient/  
また、整骨院専用CRMの比較記事（gyms.jp）でも「離反兆候スコア表示」が差別化機能として挙げられていた。  
参照: https://gyms.jp/lp/articles/seitai-sekkotsu-in-crm

現状、`src/app/actions/line-campaign.ts` の `collectTargets()` には `daysSinceLastVisit` を計算するロジックがすでに存在し、LINE配信対象の抽出に使っている。しかし受付担当が**毎日意識せずともアラートとして目に入る場所**がない。

### 提案内容
ダッシュボード（`/admin/dashboard`）のKPIカード群の下に、**「要フォロー患者 🔴」ウィジェット**を追加する。

- 条件：最終来院から **30日以上** かつ次回予約なし（既存の `collectTargets` ロジクを Server Component で再利用）
- 表示：患者名 / 最終来院日 / 経過日数 / LINE連携有無 のリスト（最大10件、多い場合は「＋○件」折りたたみ）
- アクション：各行に「LINE送信」ボタン → マーケティングページへパラメータ付きで遷移（個別送信フロー）
- 院長設定でアラート日数を20日・30日・45日から選択可

### 期待できる効果
- 受付が毎朝ダッシュボードを開いた時点でフォロー漏れを把握できる
- マーケティング送信の手間が「ダッシュボード → LINEボタン1タップ」に短縮
- 推定：月10〜20名の再来院誘導で月次売上 ¥30,000〜80,000 増（1患者2,000〜4,000円の施術費換算）

### 実装イメージ
- **関連ファイル**:
  - `src/app/admin/dashboard/DashboardClient.tsx` ← ウィジェット追加
  - `src/app/actions/analytics.ts` ← `getRiskPatients()` 関数追加（`collectTargets`の軽量版を参照）
  - `src/app/admin/settings/edit/page.tsx` ← アラート日数設定項目追加
- **難易度**: 小（既存ロジックの再利用が中心）

**優先度: 高** — 既存データと既存ロジックだけで実現でき、受付の日常業務に直接刺さる。

## 提案 2：施術完了トリガー → Google口コミ誘導LINE自動送信

**観点**: ①利用者（受付・院長）が使いやすくなる / ②データ分析・経営判断がしやすくなる

### 背景・きっかけ
Freshaは施術完了後に自動で患者へ口コミ依頼を送り、**Google Business Profileと連携してGoogleレビューを増やす機能**を標準提供している。  
参照: https://www.fresha.com/help-center/knowledge-base/clients/103752-ratings-and-reviews-overview  
Square連携アプリ（GoodReviews等）でも、決済完了をトリガーにGoogleレビュー依頼SMSを自動送信するソリューションが普及している。  
参照: https://squareup.com/us/en/app-marketplace/app/goodreviews  
日本でもGoogleマップの口コミ数は「整骨院 地名」検索での表示順位に直結しており、院として最も費用対効果の高い集客施策の一つである。

現状、受付カウンターで「完了」ステータスに更新する処理（`adminReserve.ts:completeAllActiveAppointments`）はあるが、その後LINEを送る仕組みがない。

### 提案内容
カウンターで予約を **「完了」にした直後**、LINE連携済みの患者へ自動でメッセージを送信する。

**メッセージ例（患者名入り）**:
```
{name}さん、本日はご来院ありがとうございました🙏
よろしければGoogleにご感想をお寄せください。
院の向上に活かします。
👉 [院名 Googleマップ URL]
```
- 設定項目（`/admin/settings/edit`）:
  - ON/OFF トグル（デフォルト OFF → 院ごとに有効化）
  - GoogleマップのURL（院ごとに登録）
  - 送信する最低間隔（例：同一患者に **30日以内は再送しない**）
- 「完了一括処理」でも「個別完了」でも発火
- テストモードで院長のLINEに送って確認してから有効化

### 期待できる効果
- 月10件の口コミ増加を3ヶ月続けると → Googleマップ検索順位改善 → 新規問い合わせ月 5〜15件増（業界平均コンバージョン率換算）
- 受付スタッフが「口コミお願いします」と言い出す気まずさをゼロに

### 実装イメージ
- **関連ファイル**:
  - `src/app/actions/adminReserve.ts` ← 完了処理後にLINE送信関数を呼び出し
  - `src/lib/admin-notify.ts` or `src/app/actions/reminders.ts` ← 新関数 `sendReviewRequest()`
  - `src/app/admin/settings/edit/page.tsx` ← Google Maps URL ＆ トグル追加
  - Supabase: `clinic_settings` テーブルに `google_maps_url`, `review_remind_enabled`, `review_remind_min_interval_days` カラム追加
- **難易度**: 中

**優先度: 高** — 新規患者獲得に直結。設定さえすれば受付は何もしなくて良い点が特に良い。

## 提案 3：月末収益着地予測カード（トレンド外挿 ＋ AI一言コメント）

**観点**: ②データ分析・経営判断がしやすくなる

### 背景・きっかけ
医療・クリニック向けCRM解説（archrise-works.com）では「リアルタイムの収益推移と着地見込みの可視化」が院長が最も求める機能として繰り返し言及されている。  
参照: https://www.archrise-works.com/blog/webmarketing/整骨院向けcrm  
また一般SaaSでは「今月ペースで月末に何円になるか」を計算するリニア外挿が標準的なKPIダッシュボードの機能として定着している。

現状、経営評価ページ（`/admin/evaluation`）では当月の売上合計と目標の比較はできるが、**「このペースで行くと月末には○○円になる」という予測**が表示されない。

### 提案内容
経営評価ページの先頭（KPIカードの隣）に **「月末着地予測」カード**を追加する。

**計算式**:
```
着地予測 = 当月累計売上 ÷ 経過日数 × 月の総日数
```
**表示要素**:
- 着地予測額（¥XXX,XXX）
- 目標達成率（予測額 ÷ 月間目標額、カラーバッジ: 緑80%以上/黄60〜79%/赤60%未満）
- AI一言コメント（例: 「残り12日で¥48,000必要です。今週中に自費コース1件追加しましょう。」）Geminiへ既存の `getBusinessContext` を流用して生成
- 先月同期比（同じ日数時点での比較）

### 期待できる効果
- 院長が月の途中で「このままでは厳しい」と気づき、早期にキャンペーンや追加予約枠を検討できる
- 月末ギリギリの焦りではなく、2週目時点での判断が可能になる

### 実装イメージ
- **関連ファイル**:
  - `src/app/admin/evaluation/page.tsx` ← 新カード挿入
  - `src/app/actions/evaluation.ts` ← `getMonthlyForecast()` 関数追加（当月売上合計・経過日数・月間目標を取得）
  - `src/app/actions/ai-secretary.ts` ← `generateForecastComment()` 追加（既存の `generateAnalyticsComment` を参考に）
- **難易度**: 小

**優先度: 高** — 純粋な計算追加であり実装コストが小さく、院長にとって日常使いの判断ツールになる。

## 提案 4：スタッフ個人月次ゴール設定 ＆ 達成率バッジ

**観点**: ③スタッフ管理がしやすく、スタッフのモチベーションが上がる

### 背景・きっかけ
MINDBODY代替ツール比較（rework.com）やサロン向け予約SaaS記事では、「スタッフ別の施術件数・売上の目標設定 ＆ 達成率トラッキング」が上位製品の差別化機能として紹介されている。  
参照: https://resources.rework.com/ja/tools/booking-scheduling/best-mindbody-alternatives  
Square Appointmentsでも「スタッフ別売上レポート」は標準機能だが、**自分でゴールを設定して可視化する機能**はほとんどのツールにない。

現状、リーダーボードはアクション合計ポイントのランキングのみ。ポイントが何のために貯まるか、自分が今月何を目指しているかが見えない。

### 提案内容
**マイスケジュールページ（`/admin/my-schedule`）に「今月のゴール」タブを追加**する。

- スタッフ個人が月初（1〜3日以内）に設定できる目標:
  - 担当施術件数
  - 新規患者対応件数
  - SNSタスク完了数（既存タスク機能との連動）
- リアルタイム進捗バー（Supabaseから件数を取得）
- 達成時にバッジがリーダーボードに表示（例: 🎯「11月 施術80件 達成！」）
- 院長向けのチームゴール概覧ビュー（`/admin/leaderboard` 下部に追加）: 全スタッフのゴール達成率一覧

**院長が使うケース**: 月の中間（15日前後）にチームゴール概覧を見て「今月達成が難しそうなスタッフに声をかける / シフトを調整する」という1on1のきっかけになる。

### 期待できる効果
- スタッフが「何のためにポイントを貯めているか」腑に落ち、主体的に行動しやすくなる
- 院長が個別スタッフの状態を数字で把握し、フォローのタイミングが掴めるようになる
- リーダーボードの"飾り"感がなくなり、実務KPIと連動した使われ方に進化する

### 実装イメージ
- **関連ファイル**:
  - `src/app/admin/my-schedule/page.tsx` ← ゴール設定タブ追加
  - `src/app/admin/leaderboard/page.tsx` ← チームゴール概覧セクション追加
  - `src/app/actions/security.ts` or 新 `staff-goals.ts` ← CRUD関数
  - Supabase: 新テーブル `staff_monthly_goals` (`user_id, clinic_id, year_month, goal_treatments, goal_new_patients, goal_sns_tasks, created_at`)
- **難易度**: 中

**優先度: 中** — スタッフモチベーション改善は即効性が出るまで1〜2ヶ月かかるが、長期的リテンション効果が大きい。

## 提案 5：シフト申し送りメモ（日次引き継ぎログ）

**観点**: ①利用者（受付・院長）が使いやすくなる / ③スタッフ管理がしやすくなる

### 背景・きっかけ
LINE STEP（linestep.jp）の接骨院LINE活用記事や、院内オペレーションDX事例で**「シフト交代時の情報ロスが受付ミスや患者対応の質低下につながる」**という課題が繰り返し言及されている。  
参照: https://linestep.jp/2025/11/08/chiropractic_line_booking_system/  
Fresha・Squareのように海外の予約SaaSでは「スタッフノート」や「シフトメモ」機能が標準で、次のスタッフが画面を開いた時点で当日の注意事項が見えるよう設計されている。

現状、V-ARCにはカウンターや予約ページに「今日のスタッフへの申し送り」を記録する場所がない。口頭引き継ぎのみに依存している。

### 提案内容
カウンターページ（`/admin/counter`）の最上部に **「本日の申し送り」ウィジェット**を追加する。

- 1日1件のテキストメモ（院全体共有、当日のみ表示）
- スタッフ誰でも編集可能（最終更新者・時刻を表示）
- 内容例: 「Aさん: 右肩注意、強い施術NG。保険証確認漏れあり。夕方Bさんが遅れる予定。」
- 前日分は折りたたみで参照可能（1週間分保持）
- **スタッフ予定ページ（`/admin/my-schedule`）** にも当日分のメモをプレビュー表示

### 期待できる効果
- 受付スタッフがシフト開始時に画面を開くだけで申し送りが完了
- 患者対応ミス（禁忌施術の実施、保険証確認漏れ等）の防止
- 院長が翌日の朝に前日の申し送りを参照してスタッフへフィードバックできる

### 実装イメージ
- **関連ファイル**:
  - `src/app/admin/counter/page.tsx` ← 申し送りウィジェット追加
  - `src/app/admin/my-schedule/page.tsx` ← プレビュー表示
  - `src/app/actions/staff-daily-tasks.ts` ← 既存スタッフタスク管理に `shift_memo` 型を追加、or 新テーブル `shift_handover_notes` (`date, clinic_id, content, updated_by, updated_at`)
- **難易度**: 小

**優先度: 中** — 安全性・ミス防止に直結する地味だが確実な改善。技術コストが最も低い割に、現場インパクトが大きい。
