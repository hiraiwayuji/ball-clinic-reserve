# 【週次改善提案】2026-06-28

## 今週の要約（3行）

「失客」と「スタッフ貢献の見える化」が今週のキーワード。競合の接骨院SaaS（スリーズプロ等）が LTV・離脱予測を標準機能化し、差別化要素として前面に押し出している。V-ARC には既に LINE 配信・分析・リーダーボードの土台があり、それらに「自動トリガー」「患者別スコア」「複数院横断」の層を追加するだけで、一気に経営管理ツールとして上位互換になれる。

## 提案 1：失客防止アラート ─ 「○日以上未来院リスト」の自動抽出と LINE 再来院トリガー

**観点：①②**

### 背景・きっかけ

日本の接骨院専用SaaS「スリーズプロ」は、「LTV・離脱予測・スタッフ別患者離脱分析」をCRMの核機能として訴求しており、「患者が来院しなくなる前に手を打てる」点を最大の差別化軸にしている。また trackstat.org の調査（2025）では、接骨院・整骨院で患者維持率 75% 以上を下回ると持続的成長が困難と示されている。

現状の V-ARC には LINE 配信（リマインダー・誕生日クーポン・エリア別セグメント等）の基盤はあるが、**来院間隔を監視して"来ていない患者"を自動で拾い上げる仕組みが存在しない**。スタッフが手動で顧客一覧を目視する運用は、院が忙しいほど後回しになる。

参照：
- https://reserve.threease.com/functions/crm
- https://www.trackstat.org/news/why-patient-retention-matters-more-than-new-leads-in-2025

### 提案内容

**顧客管理画面（`/admin/customers`）に「休眠リスクタブ」を追加する。**

1. **自動抽出ロジック**：各患者の最終来院日から本日までの経過日数を計算し、院が設定した「通常来院間隔」（例：週1回の患者なら14日、月2回なら21日）を超えた患者を「要フォロー」として一覧表示する。
2. **アラートバッジ**：ダッシュボード（`/admin`）や受付カウンター（`/admin/counter`）のサイドバーに「要フォロー ○名」バッジを常時表示。
3. **ワンクリック LINE 再来院メッセージ**：一覧からチェックを入れてボタン1つで、既存の LINE 配信（`line-marketing.ts`）を活用した「お体の調子はいかがですか？」メッセージを送信できる。メッセージ文はテンプレート化し、院長が編集可能。
4. **設定**：来院間隔の閾値は設定画面（`/admin/settings`）から院ごとに変更可能。

**受付・院長が何が楽になるか**：「最近来てないあの患者さんどうしてるかな」という勘頼りの業務がゼロに。月次で失客数を見て後悔するのではなく、離脱前に手を打てる。

### 期待できる効果

- 休眠患者の再来院率 5〜15% 向上（国内類似システムの報告値）
- 既存 LINE 配信基盤をそのまま活用するため追加コスト小
- 失客率の可視化により、院長が来月の目標設定（`/admin/evaluation`）をより根拠を持って行える

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/actions/adminCustomers.ts` | `getDormantPatients(thresholdDays)` 関数追加 |
| `src/app/admin/customers/page.tsx` | 「休眠リスク」タブ追加 |
| `src/app/actions/line-marketing.ts` | `sendDormantReEngagement(customerIds[])` 追加 |
| `src/app/admin/settings/page.tsx` | 閾値日数の設定 UI 追加 |
| DB | `clinic_settings` に `dormant_threshold_days` カラム追加（マイグレーション小） |

**難易度：中**（LINE 配信は既存流用、SQL は日数差分計算のみ）

### 優先度：**高**

競合が標準機能として提供済み。失客防止は来院数目標（`evaluation` の `target_patients`）に直結するため、院長・受付の両方から価値を実感しやすい。

## 提案 2：患者別 LTV スコアカード ─ 顧客カードに「生涯価値・来院継続予測」を表示

**観点：②**

### 背景・きっかけ

整骨院向けシステムを比較したリピッテ・リザービアの記事（2025）では、「LTV（顧客生涯価値）を把握していない院は、新規集客コストを過剰投下して赤字になりやすい」と指摘されている。米国の整骨院向けファイナンシャルモデル（financialmodelslab.com）では、LTV = 平均単価 × 平均来院頻度 × 継続期間 として可視化し、KPI ダッシュボードの必須指標として紹介。現状の V-ARC の顧客カードには「来院回数・初診日」程度しかなく、どの患者がビジネスに貢献しているか判断できない。

参照：
- https://financialmodelslab.com/blogs/kpi-metrics/chiropractor-office
- https://ripicle.com/osteopath/column/1463/

### 提案内容

**顧客詳細パネルに「LTV サマリ」カードを追加する。**

表示する数値（サーバー側で計算、追加 API コール不要）：

| 指標 | 計算方法 | 表示例 |
|---|---|---|
| 累計来院単価 | 自費売上合計 ÷ 来院回数 | ¥3,200 / 回 |
| 累計貢献額 | 自費売上の合計 | ¥128,000 |
| 月平均来院頻度 | 来院回数 ÷ (初診〜最終来院の月数) | 2.3回/月 |
| 継続スコア（0〜100） | 直近3ヶ月の来院間隔の安定性を数値化 | 82 |
| 推定年間貢献額 | 単価 × 月平均 × 12 | ¥89,600 / 年 |

加えて「この患者は高LTV層（上位20%）です」などのラベルを表示し、重点フォローが必要かを瞬時に判断できるようにする。

**受付・院長が何が楽になるか**：患者さんと話すとき「この方は3年通ってくれている優良患者」という背景情報が数字として見え、対応の優先度と丁寧さを自然に調整できる。院長は高LTV患者の傾向（エリア・年代・流入経路）を把握して集客戦略を立てられる。

### 期待できる効果

- 新規集客偏重から LTV 最大化へ戦略転換
- 高LTV患者属性の分析（既存 `/admin/analytics` の顧客属性分析と組み合わせ）
- 「優良患者への特別感謝メッセージ」などのパーソナル施策の根拠に

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/actions/adminCustomers.ts` | `getCustomerLTV(customerId)` 関数追加 |
| `src/app/admin/customers/CustomersTable.tsx` | 顧客ドロワーに LTV カード追加 |
| `src/app/actions/analytics.ts` | 高LTV患者の属性を集計する関数追加（analytics タブ連携） |

**難易度：小〜中**（既存売上データから計算するだけ。DB 変更なし）

### 優先度：**高**

DB 変更ゼロ、既存データの再利用。院長の意思決定に直結する数字を出すだけで体感価値が大きい。

## 提案 3：治療後 NPS アンケート ─ 来院翌日に LINE で1問送り、院長へ週次レポート

**観点：①②**

### 背景・きっかけ

NTT コミュニケーションズの医療向け NPS 解説（2025）によると、「NPS スコアが 7 未満の患者は離脱リスクが高く、7〜10 の患者の紹介率は 3〜5 倍になる」と示されている。また asklayer.io の美容室向け調査設計ガイドでは「問いは1問に絞り、24〜48時間以内に送る」ことで応答率が最大化すると紹介。現状 V-ARC の問診票（questionnaire）は初診時のみで、治療後のフィードバックループがない。Google 口コミ数は手動入力（経営評価画面）のため、実態と乖離しやすい。

参照：
- https://www.nttcoms.com/service/nps/industry/medical/
- https://asklayer.io/webアンケートツール/美容室のアンケートの作り方/

### 提案内容

**来院完了（受付カウンターで「来院完了」を打刻した翌日）に、LINE で NPS アンケートを自動送信する。**

フロー：
1. 受付カウンター（`/admin/counter`）でスタッフが「来院完了」をタップ
2. 翌朝8時に LINE メッセージ自動送信：「本日はご来院ありがとうございました！お体の具合はいかがでしょうか？ご満足度を教えてください（1〜10）」
3. 患者が LINE から数値（1〜10）を返信 → Webhook でスコアを DB に保存
4. 週次で院長の LINE に「今週のNPS: 平均 8.4（10件）」の自動サマリを通知
5. スコア 6 以下の患者は「要フォロー」フラグを顧客カードに付与（提案1の休眠リストと連携）

**受付・院長が何が楽になるか**：Google 口コミを依頼するタイミングが分かる（スコア9〜10の患者にだけ「Google にも書いていただけると嬉しいです」とフォローアップ）。クレームになる前に低スコア患者を把握できる。

### 期待できる効果

- 離脱前の早期検知により失客率低下
- Google 口コミ数の自然増（スコア高患者への誘導）
- 治療満足度の推移を経営評価の新指標として使用可能

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/actions/line-marketing.ts` | `sendNPSSurvey(lineUserId)` 追加 |
| LINE Webhook（API route） | `POST /api/line/webhook` にスコア受信処理追加 |
| `src/app/actions/adminCustomers.ts` | NPS スコア保存・取得関数追加 |
| DB | `customer_nps_responses` テーブル（customer_id, score, sent_at, responded_at） |
| `src/app/admin/evaluation/page.tsx` | 月間平均 NPS を経営評価の新指標として追加 |

**難易度：大**（LINE Webhook のメッセージ解析、スケジュール送信の仕組みが必要）

### 優先度：**中**

体験価値は高いが、LINE Webhook の実装コストが大きい。Supabase の Edge Functions + cron で解決可能。まずスコア送信〜手動集計のシンプル版から始めて、自動化は第2フェーズでも可。

## 提案 4：スタッフ貢献売上ランキング ─ リーダーボードに「担当来院数×単価」の¥軸を追加

**観点：③**

### 背景・きっかけ

Booksy の美容サロン向けスタッフ管理ガイド（2026）では、「スタッフが自分の売上貢献を数字でリアルタイムに見られることで、1件追加のクロスセルや再予約促進の動機が生まれる」と報告。実際に米国・英国の複数サロンで導入後、スタッフ1人あたり売上が平均 12% 向上したとしている。V-ARC の現在のリーダーボード（`/admin/leaderboard`）はポイント数（予約作成+5、来院完了+10 等）のみを表示しており、実際の売上への貢献度が見えない。

参照：
- https://biz.booksy.com/en-us/blog/salon-staff-management
- https://www.salonbookingsystem.com/salon-booking-system-blog/best-salon-management-software/

### 提案内容

**リーダーボード（`/admin/leaderboard`）を「今月の活動ポイント」と「担当貢献売上」の2軸で表示するよう拡張する。**

追加表示項目（担当スタッフが紐づいている予約の自費売上を集計）：

| 項目 | 内容 |
|---|---|
| 担当来院数 | 受付カウンターで完了処理した件数 |
| 担当貢献売上 | 担当した患者の自費売上合計 |
| 平均来院単価 | 貢献売上 ÷ 担当来院数 |
| 月間トレンド | 先月比アイコン（↑↓） |

加えて「今月のMVPスタッフ」バナーを受付カウンター画面のサイドに小さく表示（励みになるゲーミフィケーション要素）。スタッフ個人は自分の数字だけ見え、他スタッフの売上額は非表示にするオプションも設定可能。

**スタッフのモチベーションが上がる理由**：「今日あと2件対応したら今月の担当売上が前月超え」という具体的な目標感が生まれる。院長にとっても「どのスタッフが売上に貢献しているか」が客観的に見え、評価・インセンティブ設計の根拠になる。

### 期待できる効果

- スタッフ個人の売上意識向上
- 評価の透明性向上（主観的な評価から数値ベースへ）
- 院長の賞与・インセンティブ決定の客観的根拠に

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/actions/security.ts` | `getLeaderboard()` に貢献売上・来院数を追加 |
| `src/app/admin/leaderboard/page.tsx` | 売上軸カラムの追加、スイッチ切替 UI |
| `src/app/admin/counter/page.tsx` | MVPバナーの追加（任意） |
| DB | `appointments` テーブルに `staff_id` 紐付けが既存か確認（あれば追加 DB なし） |

**難易度：小〜中**（既存の売上データとスタッフ紐付けが整っていれば JOIN クエリ追加のみ）

### 優先度：**高**

実装コストが最も小さく、効果が即体感できる。既存リーダーボードの拡張なので UI 変更も最小限。スタッフ面談・評価の材料として即利用可能。

## 提案 5：複数院クロス KPI ダッシュボード ─ ボール・からだ・マッスル・RELAQ を1画面で比較

**観点：②**

### 背景・きっかけ

SimplyBook.me や Square Appointments の多拠点管理機能（2024-2025年版）では、「グループ全体の KPI を一画面で把握し、優秀院のベストプラクティスを他院に横展開する」機能が標準化されている。V-ARC は現状、ぼーるくんが複数院を運営しているにもかかわらず、各院のデータが完全にサイロ化されており、「からだ院はなぜ今月売上が高いのか」を横比較できる画面が存在しない。これは V-ARC が他のクリニック向けシステムにはない「多院運営者のためのSaaS」として差別化できる最大のポイントでもある。

参照：
- https://simplybook.me/en/features/multi-location （多拠点機能）
- https://digi-mado.jp/category/business/treatment-center-booking-system/ （日本市場の予約システム比較）

### 提案内容

**`/admin/analytics` に「複数院比較」タブを追加する。**

表示する比較指標（横軸：院名、縦軸：KPI）：

| KPI | ボール接骨院 | からだ | マッスル | RELAQ |
|---|---|---|---|---|
| 今月来院数 | 210 | 185 | 230 | 160 |
| 今月売上合計 | ¥840,000 | ¥680,000 | ¥910,000 | ¥590,000 |
| 新規患者数 | 12 | 8 | 15 | 7 |
| リピート率 | 78% | 82% | 71% | 85% |
| 1日平均来院 | 8.4 | 7.4 | 9.2 | 6.4 |
| 平均単価 | ¥4,000 | ¥3,677 | ¥3,956 | ¥3,687 |

グラフはバーチャートとレーダーチャートを切り替え可能。「先月比で最も伸びた院」「来院単価が最高の院」をサマリバナーで強調表示。

権限設計：院長（owner ロール）のみ全院データを閲覧可能。スタッフは自院のみ。

**院長が何が楽になるか**：毎月末に各院の院長から報告を集めて Excel で突き合わせる作業が不要に。「RELAQ のリピート率が高い理由」「マッスル院の新規が多い理由」を即座に比較し、横展開の経営判断ができる。

### 期待できる効果

- 経営会議の準備時間を大幅削減
- 優秀院のノウハウ横展開による全体底上げ
- V-ARC として「多院運営者向け経営ツール」の訴求力強化

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/actions/analytics.ts` | `getCrossClinicKPI(clinicIds[], year, month)` 追加 |
| `src/app/admin/analytics/page.tsx` | 「複数院比較」タブ追加 |
| DB | 既存の `clinic_id` 分離構造を活用（テーブル変更なし） |
| 権限 | owner ロール判定（既存 `checkAdminAuth` の role 拡張） |

**難易度：中**（データ取得は既存 analytics のロジック流用。権限制御の設計が重要）

### 優先度：**中**

ぼーるくん本人が最も恩恵を受ける機能。他院への販売時の差別化ポイントにもなる。複数院の `clinic_id` リストを設定画面から登録する仕組みが必要。

## 提案 6：スタッフ成長記録 ─ 1on1 メモ＋技術マイルストーンの院内管理

**観点：③**

### 背景・きっかけ

日本の接骨院スタッフの離職率は高く、厚生労働省の医療従事者調査（2024）でも「評価・成長実感の欠如」が主要離職理由の上位に入る。海外の美容サロン向けスタッフ管理ソフト（Booksy、Salon Iris）では「スタッフごとの技術習得チェックリスト」「院長との1on1メモ記録」「昇給・昇格の基準可視化」が標準搭載されており、スタッフが「自分の成長が見える」ことがエンゲージメント向上に直結すると報告している（biz.booksy.com）。V-ARC には勤怠・シフト・タスク・リーダーボードがあるが、スタッフの「成長の記録」を残す場所がない。

参照：
- https://biz.booksy.com/en-us/blog/salon-staff-management
- https://note.com/jgamifa/n/n883682c019a0 （国内ゲーミフィケーション業界カオスマップ 2024）

### 提案内容

**`/admin/settings/staff-schedule` に「スタッフ成長記録」タブを追加する。**

機能構成：

1. **技術マイルストーンチェックリスト**：院が設定した技術項目（例：「テーピング修得」「超音波機器操作」「骨盤矯正施術」）に対して、習得済み/研修中/未習得をスタッフごとに記録。スタッフ自身も自分の達成状況を確認できる。

2. **1on1 メモ記録**：院長とスタッフの1on1ミーティングの日時・話した内容・アクションアイテムを記録。過去のメモを時系列で振り返れる。

3. **成長グラフ**：技術習得率の推移をグラフ表示（マイルストーン達成数 ÷ 全マイルストーン数）。

4. **通知**：マイルストーン達成時にリーダーボードと連携してボーナスポイント付与（既存ポイントシステムの拡張）。

**スタッフのモチベーションが上がる理由**：「技術を覚えた」という成長が数字とチェックで記録に残り、院長からの評価根拠が透明になる。特に若いスタッフは「次に何を身につければ昇給に近づくか」が見えると努力の方向性が定まる。

### 期待できる効果

- スタッフ定着率向上（離職コスト削減）
- 院長の評価根拠の客観化（「えこひいき」感の解消）
- 技術レベルの院内標準化（どの院にいても同品質の施術）

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/admin/settings/staff-schedule/page.tsx` | 「成長記録」タブ追加 |
| `src/app/app/actions/staff-shifts.ts` | `getStaffGrowthRecord(staffId)` など追加 |
| DB | `staff_milestones`（template: milestone_id, title）, `staff_milestone_progress`（staff_id, milestone_id, status）, `staff_onetoon_notes`（staff_id, met_at, content, actions）の3テーブル |
| `src/app/actions/security.ts` | マイルストーン達成時のポイント付与ロジック追加 |
