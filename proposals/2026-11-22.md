# V-ARC 週次改善提案 2026-11-22

## 今週の要約（3行）

今週は「キャンセル空き枠の自動消化」「患者の離脱を先手で防ぐ」「スタッフが自分の時間を見える化する」3つの軸で外部事例を調査した。Square や CLINIC-CRM など海外・国内の先行事例からV-ARC固有の文脈に翻訳し、実装コスト低めで効果が出やすいものを優先した。いずれも既存機能との重複なし・追加開発のみで完結する。

---

## 提案 1：キャンセル空き枠スマートフィル（ウェイトリスト自動通知）

**観点：** ①（受付スタッフの操作負荷を下げる）

**背景・きっかけ**

Square Appointments のウェイトリスト機能（[https://squareup.com/us/en/appointments/features/waitlist-software](https://squareup.com/us/en/appointments/features/waitlist-software)）および日本の RESERVA の比較記事（[https://www.shopowner-support.net/attracting_customers/medical/bone/osteopathicclinic-reservationsystem/](https://www.shopowner-support.net/attracting_customers/medical/bone/osteopathicclinic-reservationsystem/)）を調査。Square では「キャンセルが発生した瞬間に待機中の顧客へ自動で通知し、先着で枠を確保できる」機能が有料プランの目玉になっている。V-ARC にはすでにウェイトリスト画面（`src/app/admin/waitlist/page.tsx`）があるが、スタッフが手動で確認・電話連絡しているのが現状。

**提案内容**

予約がキャンセルまたは時間変更されたとき、同じ日時・院でウェイトリストに並んでいる患者（LINE 友達登録済み）に対して自動で「空き枠が出ました。〇月〇日〇時、ご希望の場合はこちらから予約をどうぞ」という LINE メッセージを送る。

- キャンセル検知は `src/app/actions/manage-reservation.ts` のキャンセル処理後にトリガー
- 通知対象は同日時で待機中の全員（先着順・応答後に自動確定）
- スタッフ設定で「自動通知する / スタッフが確認してから通知する」を選択可能にする
- 既存の `src/app/actions/line-marketing.ts` / LINE 配信インフラを流用

**期待できる効果**

- 受付スタッフが空き枠を電話で埋める作業が不要になる
- キャンセルによる収益ロスを最小化
- 患者側も「すぐ空きが分かる」体験でリピート率向上

**実装イメージ**

- 関連ファイル：`src/app/actions/manage-reservation.ts`、`src/app/actions/adminReserve.ts`、`src/app/admin/waitlist/page.tsx`、`src/app/actions/line-marketing.ts`
- 難易度：**中**（LINE 配信と waitlist クエリを既存コードで繋ぐ。自動確定ロジックの整合性チェックが必要）

**優先度：高**
> キャンセル穴埋めは院の売上に直結。既存の waitlist インフラがあるため追加コードが少ない。受付スタッフの「あの手動電話が一番しんどい」という操作を消せる。

## 提案 2：患者「離脱リスク」スコア表示 & 自動フォローリスト

**観点：** ②（データ分析・経営判断）

**背景・きっかけ**

自由診療クリニック向け CLINIC-CRM が Gemini を使って「直近 N 日間来院なし → 離脱リスクスコア算出 → 自動フォロー」を実装（[https://note.com/meta_alchemist/n/n2d9e9cc27143](https://note.com/meta_alchemist/n/n2d9e9cc27143)）。国内接骨院向けには Lステップが「最終来院から 30 日で自動 LINE 配信」を推奨しているが（[https://linestep.jp/?p=66004](https://linestep.jp/?p=66004)）、固定 30 日ルールでは施術頻度の違いを無視してしまう。V-ARC には顧客管理（`src/app/admin/customers/`）と予約履歴データがある。

**提案内容**

各患者の「通常来院間隔」を過去の実績から自動算出し、その間隔の 1.5 倍以上が経過したら「離脱リスク: 高」と判定して顧客一覧にバッジ表示する。

- 顧客一覧（`CustomersTable.tsx`）に「要フォロー」フィルタを追加
- リスクスコアは「最後の来院から経過日数 ÷ 患者固有の平均来院間隔」で算出（Supabase の SQL 関数で計算可能）
- 要フォローリストから1クリックで LINE メッセージ（テンプレ選択式）を送れるアクション追加
- 月次経営評価画面（`src/app/admin/evaluation/`）に「今月の離脱予備軍: N 名」サマリーを追加

**期待できる効果**

- 院長が「誰が来なくなっているか」を感覚ではなくデータで把握できる
- フォロー連絡がスタッフの気づきに依存しなくなる
- 再来院率・LTV 改善につながる

**実装イメージ**

- 関連ファイル：`src/app/actions/adminCustomers.ts`、`src/app/admin/customers/CustomersTable.tsx`、`src/app/admin/evaluation/page.tsx`、`src/app/actions/line-marketing.ts`
- 難易度：**中**（来院間隔計算は Supabase SQL で書ける。ロジックのパラメータ調整が必要）

**優先度：高**
> 接骨院の集客コストの多くは新規顧客獲得。既存患者を逃さない施策は即効性が高い。外部からのリサーチで「固定 N 日ルールより個人間隔ベース」というアプローチは他社との差別化になる。

## 提案 3：施術改善グラフの患者向け QR 共有（体験価値の見える化）

**観点：** ①（患者体験・リピート率向上）

**背景・きっかけ**

Healthcare CRM 2026年の最新トレンドとして「患者自身が自分の改善データを見られること（patient-facing progress sharing）」が来院継続の有力な施策として挙げられている（[https://www.grazitti.com/blog/the-crm-reckoning-why-healthcares-data-debt-is-now-a-clinical-risk/](https://www.grazitti.com/blog/the-crm-reckoning-why-healthcares-data-debt-is-now-a-clinical-risk/)、[https://www.groovyweb.co/blog/healthcare-crm-software-development-2026](https://www.groovyweb.co/blog/healthcare-crm-software-development-2026)）。V-ARC にはトレーニング・問診アセスメント機能（`src/app/admin/training/`）があり、施術ごとにスコアを記録しているが、患者本人がその推移を見る手段がない。

**提案内容**

患者のアセスメントスコア推移（例：痛み 8→5→3、可動域 4→6→8 など）を折れ線グラフにした「改善レポート」ページを生成し、院内 iPad または施術後 LINE メッセージで患者に共有できるようにする。

- `/public/patient-report/[token]` のような公開 URL（トークン認証、30 日有効）を生成
- グラフは既存の Recharts ライブラリで実装（`src/app/admin/analytics/page.tsx` と同様）
- 院長・スタッフが「共有ボタン」を押すと LINE メッセージに URL が入力済みで開く

**期待できる効果**

- 「施術の効果が見える → 続けよう」という動機づけ強化
- 施術士のプロフェッショナリズム可視化による信頼感向上
- 患者が SNS でシェアするケース（口コミ）も期待できる

**実装イメージ**

- 関連ファイル：`src/app/admin/training/[customerId]/page.tsx`、`src/app/admin/training/[customerId]/AssessmentForm.tsx`、`src/app/actions/training.ts`
- 新規：`src/app/patient-report/[token]/page.tsx`（公開ルート）
- 難易度：**小〜中**（グラフ描画は既存ライブラリ、トークン生成のみ新規実装）

**優先度：中**
> 競合システムにはほぼない機能。患者の「続けよう」という決意を引き出す体験設計として尖っている。トークン有効期限の管理に慎重さは必要。

## 提案 4：スタッフ月次振り返りシート + 院長コメント機能

**観点：** ③（スタッフ管理・モチベーション向上）

**背景・きっかけ**

カオナビのユーザー事例「ブランコ青山」（美容サロン）では、スタッフが毎月末に活動報告を提出し店長がフィードバックコメントを入れる仕組みを導入後、「退職者数が 7 名 → 2 名に減少」と報告（[https://www.kaonavi.jp/showcase/sam/](https://www.kaonavi.jp/showcase/sam/)）。V-ARC の経営評価画面（`src/app/admin/evaluation/`）は院長が月次目標と AI 提案を閲覧する機能だが、スタッフ側から「自分の振り返り」を入力・提出する導線がない。

**提案内容**

スタッフがログイン後、「今月の振り返り」フォームを月 1 回記入して送信できる機能を追加する。

- 入力項目（5 項目以内）：①今月の一番の出来事 ②うまくいかなかったこと ③対応件数・売上の自己評価 ④来月の目標 ⑤院への一言
- 提出後は院長側（`src/app/admin/evaluation/page.tsx` or 新規タブ）に「スタッフ振り返り一覧」が表示される
- 院長がコメントを入力するとスタッフへ LINE または画面通知
- 既存のシフト・スタッフ管理（`src/app/admin/settings/staff-schedule/`）とユーザー情報を紐づけ

**期待できる効果**

- スタッフが「見てもらえている」という実感 → 離職率低下
- 院長が個別面談なしで全スタッフの状況を把握
- 月次振り返りの蓄積がスタッフ評価の客観的根拠になる

**実装イメージ**

- 関連ファイル：`src/app/admin/evaluation/page.tsx`、`src/app/admin/settings/staff-schedule/`、`src/app/actions/evaluation.ts`
- 新規テーブル：`staff_monthly_reflections`（user_id, year_month, answers JSON, manager_comment, submitted_at）
- 難易度：**中**（DB スキーマ追加 + フォーム UI + 通知連携）

**優先度：中**
> スタッフ定着は多院展開の最大コスト変数。ゲーミフィケーション（ランキング）で動機づけは既に実装済みなので、「院長との対話」という横軸を加えることで二段構えになる。

## 提案 5：スタッフ別 時間帯稼働率ヒートマップ

**観点：** ②③（経営判断 + スタッフ管理）

**背景・きっかけ**

美容サロン向け Rework のデータ分析ガイド（[https://resources.rework.com/ja/libraries/beauty-center-growth/data-driven-decisions-salon-owners](https://resources.rework.com/ja/libraries/beauty-center-growth/data-driven-decisions-salon-owners)）では、「月間総売上だけ見て安心し、スタイリスト別・時間帯別の稼働率低下を見落とす院長が多い」と指摘。同様に V-ARC の売上分析（`src/app/admin/sales/analytics/`）はスタッフ別売上ランキングを表示しているが、「○曜日の○時台に A さんの予約がガラ空き」というスロット単位の可視化はない。

**提案内容**

スタッフ × 時間帯（30 分刻み）のヒートマップを経営評価または分析画面に追加する。

- 横軸：月〜日、縦軸：9:00〜20:00（30 分刻み）
- セルの色：稼働率 0% 〜 100%（白 → 深い緑のグラデーション）
- スタッフをドロップダウンで切り替えて比較
- 「過去 4 週間の平均」と「今週」を並べて表示
- データソース：既存の予約テーブル（`adminReserve.ts`）をクエリするのみ

**期待できる効果**

- 院長が「特定スタッフの水曜午後が常に空いている」を即座に発見 → シフト最適化やキャンペーン施策につなげる
- スタッフ本人も自分の稼働を見て「もっと予約を入れよう」という意識が生まれる
- 複数院比較にも使える（院 A vs 院 B の同時間帯稼働率）

**実装イメージ**

- 関連ファイル：`src/app/admin/analytics/page.tsx` or `src/app/admin/sales/analytics/page.tsx`、`src/app/actions/analytics.ts`
- CSS Grid または SVG でヒートマップを描画（Recharts の CartesianGrid でも代替可）
- 難易度：**中**（SQL 集計クエリは複雑だがロジック自体は明快、UI 描画に工数）

**優先度：中**
> 現状の「スタッフ別売上ランキング」だけでは空き時間の問題が見えない。シフト設計・集客施策の質が上がる分析インフラ。複数院の院長が使う場面で差が出やすい。
