# V-ARC 週次改善提案 2026-10-11

## 今週の要約（3行）

Zenoti・MINDBODY などの海外サロン SaaS は「来院間隔の分析 × 自動フォロー」を核に顧客 LTV を最大化している。国内では STORES予約が 2022 年にβ提供した顧客セグメント分析が、現在では標準に近い機能となりつつある。V-ARC が次に投入すべきは、**既存データを使った離脱予防・LTV 可視化・スタッフ動機づけの仕組み化**の 3 点と判断する。

---

## 提案一覧

### 提案 1｜離脱リスク患者アラート ＋ ワンクリック LINE フォロー

**観点**: ①利用者が使いやすくなる ／ ②データ分析・経営判断がしやすくなる

**背景・きっかけ**

Zenoti の公式マーケティングページ（https://www.zenoti.com/en-uk/platform/marketing）では、「来店が途絶えた顧客を自動検知して適切なタイミングにアプローチする」機能が主要訴求点の一つになっている。日本向けの記事でも「患者が来なくなる主因は『忘れた』であり、施術後数日でのフォローが 2 回目来院を左右する」と指摘されている（https://rabiloo.co.jp/blog/clinic-patient-retention）。V-ARC は来院履歴の data は持っているが、離脱リスク患者を一覧化してフォローする UI が存在しない。

**提案内容**

- **来院間隔の自動計算**: `src/app/actions/analytics.ts` の `getCustomerAnalytics` から各患者の直近来院日を取り、「前回来院から N 日経過」を算出する。
- **アラートリスト画面**: `/admin/analytics` または `/admin/counter` の下部に「要フォロー患者（30 日以上未来院）」セクションを新設。患者名・最終来院日・来院間隔・累計来院回数を一覧表示。
- **ワンクリック LINE 送信**: 各行に「フォローメッセージを送る」ボタンを設置。クリックすると既存の `src/app/actions/line-marketing.ts` の送信 API を呼び出し、「○○さん、最近お体の調子はいかがですか？いつでもお気軽にご来院ください」的なテンプレートメッセージを LINE で送信。送信済みフラグを DB に記録し、二重送信を防ぐ。
- **閾値設定**: 設定画面からアラート閾値（デフォルト 30 日）を変更できるようにする。

**期待できる効果**

- 受付スタッフが毎朝 1 分でフォロー漏れを確認できる → 離脱率の低下
- 「忘れていた」患者の再来院が月 2〜3 件増えれば月次売上に直接寄与

**実装イメージ**

- 関連ファイル: `src/app/admin/analytics/page.tsx`、`src/app/actions/analytics.ts`、`src/app/actions/line-marketing.ts`
- 新規 DB カラム: `customers` テーブルに `follow_up_sent_at` を追加、または `line_follow_up_logs` テーブルを新設
- 難易度: **中**（既存の LINE 送信 API と来院データを繋げるだけで基本動作可）

**優先度**: **高** — 既存データを活かすだけで実装でき、直接的な売上インパクトが見込める。Zenoti が最重要機能として押し出している「lapsed guest 再活性化」の日本版。

### 提案 2｜患者別 LTV スコア ＆ セグメントタグ

**観点**: ②データ分析・経営判断がしやすくなる ／ ①利用者が使いやすくなる

**背景・きっかけ**

STORES予約が 2022 年に β 提供した「顧客分析機能」は、患者を性別・年代で分析し販促ターゲットを絞り込む機能（https://ecnomikata.com/ecnews/37302/）。同機能は現在、類似サービスの標準機能になりつつある。V-ARC の `/admin/customers` 画面では顧客情報の一覧表示はできるが、LTV や来院頻度によるセグメントの可視化はない。「誰が院の収益を支えているか」が分からない状態では、院長が打ち手を選べない。

**提案内容**

- **LTV スコア自動計算**: 来院履歴 × 自費売上を集計し、「累計売上額」「平均来院頻度（月）」「最終来院からの経過日数」の 3 軸で患者ごとのスコアを算出。
- **セグメントタグの自動付与**: スコアに基づき 4 カテゴリを自動付与。
  - 🌟 **VIP**: 累計売上上位 20% かつ月 1 回以上来院
  - 💚 **ケア中**: 定期的に来院中（月 0.5 回以上）
  - ⚠️ **要フォロー**: 以前は定期来院していたが 30 日以上来院なし
  - 💤 **離脱**: 90 日以上来院なし
- **顧客一覧へのタグ表示**: `src/app/admin/customers/CustomersTable.tsx` にセグメントバッジを追加。フィルターでセグメントを絞り込めるようにする。
- **経営評価ページへのサマリー追加**: `/admin/evaluation` の月次レポートに「VIP 患者数: XX 人 / 今月の離脱患者: XX 人」を追記。

**期待できる効果**

- 「VIP 患者への優先対応」や「要フォロー患者への先手アクション」が判断しやすくなる
- 院長が「今月は VIP が 3 人減った → 理由を深堀り」というアクションを取れるようになる

**実装イメージ**

- 関連ファイル: `src/app/admin/customers/CustomersTable.tsx`、`src/app/actions/adminCustomers.ts`、`src/app/admin/evaluation/page.tsx`
- 難易度: **中**（計算ロジックは Server Action に集約、CustomersTable に表示追加）

**優先度**: **高** — 顧客 DB が育ってきた今が最もインパクトのある追加タイミング。

### 提案 3｜来院完了トリガーの Google 口コミ自動依頼 LINE

**観点**: ①利用者が使いやすくなる ／ ②データ分析・経営判断がしやすくなる

**背景・きっかけ**

Millennium Systems の 2025 年レポート（https://www.medestheticsmag.com/home/article/22934105/millennium-systems-intl-5-toprated-marketing-automation-tools-for-salons-in-2025）では、「施術後の自動フォロー（口コミ・満足度）メッセージ」がトップ 5 のマーケティング自動化機能の 1 つに挙げられている。現状の V-ARC では Google 口コミ数は院長が手動で `/admin/evaluation` に入力しているが、依頼は担当者が手動でしている（orしていない）状態。口コミが獲れる一番のタイミングは「来院直後の感謝感情が高い瞬間」。

**提案内容**

- **来院完了 → 口コミ依頼トリガー**: `/admin/appointments` で担当者が「来院完了」ステータスに変更した瞬間に、設定された遅延時間（デフォルト: 2 時間後）で LINE メッセージを自動配信。
- **メッセージ内容例**: 「本日はご来院ありがとうございました！もしよろしければ、Google での口コミをいただけると大変励みになります → [口コミリンク]」
- **LINE 連携済み患者のみ対象**: LINE 未連携患者はスキップ（または受付での手動依頼催促を表示）。
- **送信済み管理**: 同一患者への重複送信を避けるため「前回口コミ依頼から X 日以内は送らない」ルールを実装（デフォルト: 30 日）。
- **設定画面**: `/admin/settings` に Google 口コミ URL と遅延時間の設定欄を追加。
- **集計への反映**: 口コミ依頼送信数を評価ページのレーダーチャートの「口コミ」軸に関連づけ（将来的には Google API で自動取得も検討）。

**期待できる効果**

- 口コミ獲得の機会損失をゼロに近づける（依頼を「忘れる」が最大の敗因）
- Google 評価数の増加 → 新規患者の検索流入増加

**実装イメージ**

- 関連ファイル: `src/app/actions/adminReserve.ts`（来院完了ステータス変更 action）、`src/app/actions/line-marketing.ts`、`src/app/admin/settings/page.tsx`
- 新規テーブル: `review_request_logs (customer_id, sent_at, appointment_id)`
- 難易度: **中**（既存 LINE 送信基盤の流用、遅延実行は Supabase Edge Function + pg_cron で対応）

**優先度**: **高** — 実装コストが比較的小さく、口コミ増加 → 集客への効果が明確。

### 提案 4｜スタッフ 1on1 ログ ＆ 目標トラッキング

**観点**: ③スタッフ管理がしやすく、スタッフのモチベーションが上がる

**背景・きっかけ**

医療現場の 1on1 ガイド（https://www.skillty.jp/article/1on1-healthcare）では、「適切なフィードバックと具体的な指導を受けることで自己成長が実感され、組織全体の士気が向上する」と説明されている。V-ARC にはリーダーボードによるゲーミフィケーションはあるが、**スタッフ個人の目標・成長を院長と共有する場** がない。1on1 ログがないと「感謝・改善点・次の目標」が伝わらず、リーダーボードのポイントだけでは中長期モチベーション維持に限界がある。接骨院スタッフのモチベーション記事（https://www.hone-u.com/column/cate7b1zb/noteok1zb.php）でも「承認欲求を満たす」「意見を出しやすくする」ことが重要と指摘されている。

**提案内容**

- **1on1 記録画面の新設**: `/admin/settings/staff-schedule` または新規 `/admin/staff-oneonone` に 1on1 ログ画面を追加。
- **記録項目**:
  - 日付・対象スタッフ
  - 今月のがんばり（テキスト、院長が書く）
  - 課題・改善ポイント（テキスト）
  - 来月の目標（テキスト）
  - スタッフ本人からのコメント欄（スタッフが自分のアカウントで書き込み可）
- **リーダーボードとの連携**: `/admin/leaderboard` でスタッフのポイントを見ながら、そのスタッフの 1on1 へのリンクを追加。「今週の MVP への感謝メモを残す」アクションにも +5pt を付与。
- **過去ログの一覧表示**: スタッフごとの成長ストーリーが時系列で振り返れる。
- **AI コメント補助**: 入力欄にフォーカスした際に「このスタッフの先月ポイント・行動数」を参照し、「先月は予約対応が XX 件で全スタッフ中 2 位でした。特に〜〜が評価できます」的なドラフトを AI が生成。

**期待できる効果**

- 「ポイントを稼ぐ」だけでなく「なぜ頑張るか」が可視化される → 離職率低下
- 院長が過去ログを見ながら 1on1 の準備を 5 分で終えられる

**実装イメージ**

- 関連ファイル: `src/app/admin/leaderboard/page.tsx`、`src/app/admin/settings/staff-schedule/` 配下に新タブ追加
- 新規テーブル: `staff_ooo_logs (staff_user_id, clinic_id, date, manager_praise, issue, next_goal, staff_comment)`
- 難易度: **中**（CRUD + AI 補助付きフォーム）

**優先度**: **中** — 直接的な売上より定性的なインパクトだが、スタッフ定着はジワジワ効く。リーダーボードとセットで「認める仕組み」として完成する。

### 提案 5｜受付カウンター「今日の壁スコア」ライブダッシュボード

**観点**: ①利用者が使いやすくなる ／ ③スタッフのモチベーションが上がる

**背景・きっかけ**

Zenoti の多店舗向けエンタープライズダッシュボード（https://www.zenoti.com/blog/zenoti-ups-the-ante-for-multi-location-spa-and-salon-management-with-enterprise-reporting-and-dashboards）は、リアルタイムで各拠点の KPI を表示する壁面ダッシュボード機能を売りにしている。V-ARC の `/admin/counter` にはすでに受付カウンター機能があるが、「今日が今どのくらいの状態か」を **スタッフ全員がパッと見渡せる大型表示** がない。来院数・売上が目標に対して何パーセントかをリアルタイムで見せることは、スタッフの行動変化（積極的な声かけ・提案など）に直結する。

**提案内容**

- **「壁モード」ボタンを /admin/counter に追加**: クリックすると全画面表示に切り替わり、タブレットや PC モニターに映し出せる。
- **表示内容（大型フォント）**:
  - 今日の来院数 / 今日の目標来院数（例: 18/25 人、達成率 72%）
  - 今日の自費売上 / 今日の目標（例: ¥45,000/¥60,000）
  - 次の空き枠（例: 14:00〜 空き 3 枠）
  - 今週のリーダーボード TOP 3（リアルタイム更新）
- **背景色変化**: 目標達成率に応じて背景が緑〜黄〜赤に変化（心理的アクセル）。
- **自動更新**: 30 秒ごとに Supabase Realtime または SWR で再フェッチ。
- **日次目標の設定**: `/admin/settings` で「曜日別来院目標」「曜日別売上目標」を設定でき、壁モードに反映される。

**期待できる効果**

- スタッフが「今日あと何人必要か」を意識して動ける → 積極的な声かけ・リピート提案が増える
- リーダーボード TOP 3 の表示でゲーミフィケーションが日常化する

**実装イメージ**

- 関連ファイル: `src/app/admin/counter/page.tsx`、`src/app/actions/analytics.ts`（日次集計）、`src/app/admin/settings/page.tsx`
- 日次目標の DB: `src/app/actions/settings.ts` に曜日別目標を追加（または既存の月次目標を活用）
- 難易度: **小〜中**（表示ロジックは既存データの組み合わせ、全画面 CSS は簡単）

**優先度**: **中** — 実装コストが小さく、スタッフが「楽しく」使える体験になる。リーダーボードと組み合わせると相乗効果が高い。
