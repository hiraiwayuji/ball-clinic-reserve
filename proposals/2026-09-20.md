# 週次改善提案 — 2026-09-20

## 今週の要約（3行）

美容室・サロン業界の「来院後フォロー自動化でリピート率38%→71%」事例と、接骨院CRMへの RFM セグメント分析の普及を外部リサーチで確認。クリニックスタッフマネジメント研究からは「個人数値目標の見える化」と「月1回 1on1 面談の記録化」が離職率低下の最有力施策であると裏付けられた。今週は「患者を引き留める仕組み（提案1・2・5）」と「スタッフが数字で自分の成長を実感できる仕組み（提案3・4）」に絞って5案を提出する。

---

## 提案1: 施術後24時間 NPS 自動 LINE + Google クチコミ誘導

- **観点**: ① 利用者が使いやすくなる / ② 経営判断がしやすくなる

### 背景・きっかけ

美容室でのリピート率向上実践研究（haward-joyman.com）で「来院後 24時間・1か月・2か月のシナリオ配信がリピート率を最大化する」と報告されている。また CLIUS 電子カルテコラム（clius.jp 2026/04/23「来院が止まった患者をどう把握するか」）でも、来院後フォローの欠如が離脱の主因として挙げられている。
SimplyBook.me（simplybook.me/ja/booking-system-features-and-integrations）は予約完了後のレビュー自動リクエスト機能を標準搭載しており、日本でも導入院が増えている。

V-ARC には誕生日クーポン・休眠患者フォローはあるが、**「施術直後に感想を聞く」フィードバックループが存在しない**。Google レビューの獲得も完全に手動・口頭依存。

### 提案内容

来院ステータスが「完了（checkin_status = completed）」に変わった **24時間後**、LINE 経由で自動送信:

```
本日はありがとうございました🙏 ○○接骨院です。
今日の施術はいかがでしたか？ひと言教えてください。

⭐ とても良かった → [yes リンク]
😐 普通でした → [neutral リンク]
😟 イマイチでした → [ng リンク]
```

- ⭐ 回答者 → 「ありがとうございます！よろしければ Google でもご感想をお願いします（30秒）」+ Google Maps URL
- 😟 回答者 → 「ご不満をこっそり教えてください」→ 院長専用 LINE DM に転送（他スタッフ不可視）
- 回答率・スコア推移をマーケティングページの新タブ「口コミ・満足度」に表示

### 期待できる効果

- Google レビュー数が月 3〜5 件増（口コミ掲載順位改善 → 新患獲得）
- 不満患者の離脱前検知（今は離れてから気づく）
- 満足度データの蓄積 → 院別・施術者別・曜日別の分析が可能に

### 実装イメージ

| 要素 | 詳細 |
|---|---|
| 関係ファイル | `src/app/actions/line-marketing.ts`, `src/app/actions/adminReserve.ts` |
| 新規 | DB テーブル `post_visit_nps`（appointment_id, score, created_at） |
| トリガー | Supabase Scheduled Edge Function で appointments の completed を 24h後にチェック |
| LINE | 既存 Messaging API の push 送信を流用 |
| **難易度** | **中** |

**優先度**: **高**
- Google レビューは新患獲得に直結。実装コストに対して ROI が最も高い。既存の LINE インフラを活かせる。

## 提案2: 患者 RFM スコアリング + 自動セグメントタグ表示

- **観点**: ② データ分析・経営判断がしやすくなる

### 背景・きっかけ

競合システム「リピクル」「ReCOMa」の機能比較（aspicjapan.org, orend.jp, re-coma.net）から、2026年の接骨院 CRM には **RFM 分析（Recency・Frequency・Monetary）による患者セグメント分類が標準装備**されつつあることを確認。BOXIL 2026年版 NPS サービス一覧でも「セグメント × メッセージング精度」が差別化ポイントとして挙げられている。

V-ARC の顧客一覧には `lastVisit` / `appointmentCount` / `created_at` があるが、3軸を複合したセグメントスコアは存在せず、現在の休眠患者フォローも「未来院日数の単軸フィルター」に留まっている。

### 提案内容

顧客一覧画面にセグメントバッジを自動付与:

| バッジ | 条件（目安） | アクション |
|---|---|---|
| 🟢 **VIP 常連** | 来院 10 回超 ＆ 最終来院 14 日以内 | VIP 限定キャンペーン送信 |
| 🟡 **要フォロー** | 来院 3 回超 ＆ 最終来院 30〜60 日 | 呼び戻し LINE |
| 🔴 **休眠予備軍** | 来院 2〜5 回 ＆ 最終来院 60〜90 日 | 「お久しぶり」クーポン |
| ⚪ **一回限り** | 来院 1 回 ＆ 初回から 30 日超経過 | ウェルカムフォロー |

顧客一覧の「タブ」として「セグメント別」フィルターを追加し、既存の「まとめて LINE 送信」機能と連携。例: 「🟡 要フォロー 23 名にまとめて送る」ボタン。

### 期待できる効果

- 「誰に何を送るか」を 0 秒で判断できる（現在は全顧客リストをスクロールして探す）
- 要フォロー患者への施策スピードが向上
- セグメント別の施策効果検証が可能に（VIP のみにキャンペーン → 来院率変化を比較）

### 実装イメージ

| 要素 | 詳細 |
|---|---|
| 関係ファイル | `src/app/actions/adminCustomers.ts`（getCustomers に rfmSegment 追加） |
| 関係ファイル | `src/app/admin/customers/CustomersTable.tsx`（バッジ表示・セグメントフィルター追加） |
| DB 変更 | 不要（lastVisit, appointmentCount を使う計算値） |
| **難易度** | **小〜中** |

**優先度**: **高**
- DB スキーマ変更不要・実装コストが小〜中のわりに、マーケティング精度と受付スタッフの判断スピードが大幅改善。

## 提案3: スタッフ個人月次目標 × マイ達成率ダッシュボード

- **観点**: ③ スタッフ管理がしやすく、モチベーションが上がる

### 背景・きっかけ

サロンスタッフのモチベーション向上研究（kuroco.team「サロンスタッフの育成術・自発的チームの作り方」, beaute-p.com「評価制度でサロンの指針を示そう」）で、**「数値に基づく客観的な個人評価の見える化」が自発性を引き出す最大要因**であると繰り返し報告されている。接骨院 KPI 設計ガイド（hone-u.com）でも「スタッフ別の担当患者数・指名数の月次目標設定が離職率低下に効果あり」と記載。

V-ARC のリーダーボードは競争を促す仕掛けだが、「**今月の自分の目標に対して今どこにいるか**」という個人軸の進捗は見えない。ポイントが低めのスタッフは比較で萎縮するリスクがある。

### 提案内容

`/admin/my-schedule`（スタッフ個人ページ）に「マイ月次目標カード」を追加:

```
┌──────────────────────────────┐
│  📊 9月の目標                │
│  担当完了件数 ██████░░  62%  │  目標50件 / 現在31件
│  自費施術件数 ████░░░░  45%  │  目標20件 / 現在9件
│  遅刻 0 日達成   ✅ 今月0日  │
└──────────────────────────────┘
```

- 目標は毎月スタッフ自身が入力（院長が上限を設定可）
- 目標達成時はパーティクルアニメーションで祝福
- 院長は `/admin/settings/staff-schedule` から全スタッフの目標・達成率を一覧確認・編集可能
- 月次リセット: 翌月 1 日 0 時に新月目標入力を促す LINE 通知

### 期待できる効果

- 「あと○件で達成！」という内発的動機付け（ゲーミフィケーション）
- 院長が個別面談で「目標の根拠」を話し合えるようになる（提案4 の 1on1 と連携）
- スタッフが自分で目標を設定することで ownership が生まれる

### 実装イメージ

| 要素 | 詳細 |
|---|---|
| 新規 DB | `staff_monthly_goals`（clinic_id, user_id, month, goal_type, target_value） |
| 関係ファイル | `src/app/admin/my-schedule/page.tsx`, `src/app/actions/staff-schedule.ts` |
| **難易度** | **中** |

**優先度**: **中**
- リーダーボードの「補完」として機能し、スタッフ満足度・定着率に寄与。スタッフ1人の採用・研修コストは50〜100万円と言われるため、定着への投資効果は高い。

## 提案4: 1on1 ミーティング記録 + 次回アクション管理

- **観点**: ③ スタッフ管理がしやすく、モチベーションが上がる

### 背景・きっかけ

PHC 株式会社「クリニックを発展させるスタッフマネジメント」セミナーレポート（phchd.com）で、**「月 1 回 10〜15 分の 1on1 フィードバック面談を設け、評価点と理由を本人に共有し、次のアクションまで確認する院はスタッフ定着率が高い」**と報告されている。

V-ARC にはシフト・勤怠・給与管理はあるが、「院長とスタッフが話した内容を残す」機能がない。面談が口頭だけだと「先月話したこと、どうなった？」のトラッキングができず、同じ悩みが繰り返されるリスクがある。

### 提案内容

新規ページ `/admin/staff-one-on-one`（または設定タブ）:

- 院長が「1on1 を記録」ボタン → スタッフ選択 → 以下を入力:
  - 実施日、よかった点、改善点、次のアクション（具体的）、次回面談予定日
- スタッフは自分の過去の記録のみ閲覧可能（他スタッフの記録は非表示）
- 次回面談日が 3 日前に近づいたら、ダッシュボードに「○○さんとの 1on1 が 3 日後」バナーを表示
- **AI オプション**: 「このスタッフの最近のリーダーボードスコア・欠勤状況を踏まえて、今月の 1on1 で聞くべきことを 3 つ提案して」→ AI 秘書機能と連携

### 期待できる効果

- 面談の質が上がり、スタッフが「自分のことを気にかけてもらっている」と感じる
- 課題 → 改善 → 確認のサイクルが回る（「先月指摘した件、どうなった？」がログから確認できる）
- 多院展開時でも各院スタッフの状況を院長が俯瞰可能

### 実装イメージ

| 要素 | 詳細 |
|---|---|
| 新規 DB | `staff_one_on_ones`（id, clinic_id, staff_user_id, held_at, good_points, improve_points, next_actions, next_scheduled_at） |
| 関係ファイル | 新規ページ、`DashboardClient.tsx`（リマインダーバナー追加） |
| AI オプション | `src/app/actions/ai-secretary.ts` に 1on1 提案プロンプト追加 |
| **難易度** | **中** |

**優先度**: **中**
- 採用難時代にスタッフ定着は最重要経営課題のひとつ。ツール自体の実装コストは重くなく、使われれば自然と習慣になる。

## 提案5: 患者キャンセル理由の構造化収集 + 月次離脱傾向チャート

- **観点**: ② データ分析・経営判断がしやすくなる

### 背景・きっかけ

2026年美容室失客研究（astaff.net「美容室の失客理由 No.1 は"なんとなく"〜データを活用した失客防止策」）で、**「失客理由を聞いていない院はデータなしで手を打てない」**という課題が明示されている。院が「患者数が減っている」と気づいても、「費用が高いから？治ったから？遠くなったから？」が分からないと施策を打ちようがない。

V-ARC の `cancel_kind` フィールドは `unexcused`（無断）/ `approved`（了解済み）/ `clinic_reason`（院都合）の 3 分類のみで、**患者が「なぜ来なくなったか」の理由データが全く蓄積されていない**。

### 提案内容

患者都合のキャンセルを処理する際（受付カウンターまたは予約一覧から操作時）、受付スタッフが理由コードを 1 クリックで選択するモーダルを追加:

```
キャンセル理由（任意・1 つ選択）：
○ 症状が改善した（卒業）
○ 転院・他院へ
○ 費用の都合
○ 時間・スケジュールの都合
○ 遠距離・引越し
○ 不満あり（詳細は院長確認）
○ 不明・聞けなかった
```

分析ページ（`/admin/analytics`）に新セクション「キャンセル理由分析」:
- 月別の理由別キャンセル件数の積み上げ棒グラフ
- 「費用の都合」が多い月 → 自費施術の価格見直しシグナル
- 「症状改善」が多い月 → 予防ケア・セルフケア提案の強化シグナル
- 「不満あり」は院長専用アラートに即時通知

### 期待できる効果

- 「なぜ離れているか」が初めてデータ化される
- 施策の投資先（集客？リピート？価格見直し？）を根拠つきで判断できる
- 「不満あり」をリアルタイムで拾い、院長がその日のうちにフォロー電話できる

### 実装イメージ

| 要素 | 詳細 |
|---|---|
| DB 変更 | `appointments` テーブルに `cancel_reason_code` カラム追加（varchar, nullable） |
| 関係ファイル | `src/app/admin/counter/page.tsx`（キャンセル時モーダル追加） |
| 関係ファイル | `src/app/actions/adminReserve.ts`（classifyCancellation に reason_code 引数追加） |
| 関係ファイル | `src/app/admin/analytics/page.tsx`（新チャートセクション追加） |
| **難易度** | **中** |

**優先度**: **中**
- 「データが取れないと何も改善できない」問題を解決する基盤施策。入力は 1 クリックで受付の負担は最小。データが溜まるほど価値が上がる。
