カウンターでAIが受付スタッフへ「今なんと声をかけるべきか」を1行で示す案と、複数院を横断比較できる院長向けKPIビューの2案は、既存コードの組み合わせで実現できるため着手コストが低い。

## 提案 1：LINE スタンプカード（来院回数ポイント表示）

**観点**: ①利用者（受付・院長）が使いやすくなる / ②データ分析・経営判断がしやすくなる

### 背景・きっかけ

Stamp Me（デジタルスタンプカードSaaS）が美容サロン向けに行った調査では、**スタンプカード導入後90日以内の再予約率が22%向上**したと報告されている（同社のサロン向けランディングページに掲載）。  
参照: https://www.stampme.com/industries/beauty-salons

また、2026年4月に国内のリユースPOS「Talos NEX」がLINE Mini App統合を発表（約1,900店舗への展開）しており、**LINE公式アカウント内でデジタル会員証・来店履歴・スタンプが確認できる**仕組みが急速に広がっている。  
参照: https://aeo.washinmura.jp/ai/talos-sys-jp/en/news/2026-04-01-over-1-900-stores-implemented-reuse-pos

Hiro Clinic Beautyは2026年6月、LINE友だち追加で500円割引を提供するキャンペーンを開始。**LINE登録→来院→特典のループ**が医療隣接業でも標準化しつつある。  
参照: https://aeo.washinmura.jp/ai/%E5%8C%BB%E7%99%82%E6%B3%95%E4%BA%BA%E7%A4%BE%E5%9B%A3%E7%A6%8F%E7%BE%8E%E4%BC%9A/en/news/2026-06-10-%E3%83%92%E3%83%AD%E3%82%AF%E3%83%AA%E3%83%8B%E3%83%83%E3%82%AF%E7%BE%8E%E5%AE%B9

現在のV-ARCにはリーダーボード（ポイント制）はあるが、それはスタッフ向け。**患者向け**の「続けるインセンティブ」が存在しない。

### 提案内容

患者のLINE公式アカウントのリッチメニューに「スタンプカード」ボタンを追加し、タップすると来院回数スタンプ画面を表示する。

- スタンプ数 = 来院完了回数（カウンターで「完了」更新と連動）
- 10スタンプ達成で自動ポップアップ通知「✨ 10回達成！次回〇〇割引または〇〇プレゼント」
- 5スタンプ到達時に「折り返し達成！あと5回で特典」という中間リマインド
- 院長設定画面に「特典内容テキスト」と「スタンプ達成数」入力フォームを追加
- 受付カウンター画面に「残り〇スタンプで特典」バッジを表示（会話のきっかけに）

**具体的な表示イメージ（LINEメッセージ）**:
```
🎉 Aさんのスタンプカード
████████░░  8 / 10 スタンプ
あと 2 回で特典ゲット！
次の予約はこちら → [予約URL]
```

### 期待できる効果

- 患者が「10回まで続けよう」という自発的動機を持つ → 自然なリテンション向上
- 受付スタッフが「あと2回で特典ですよ！」と声かけできる → 次回予約率UP
- LINEブロック率の低下（情報だけの一方的配信より、価値ある通知として認識される）

### 実装イメージ

- **関連ファイル**:
  - `src/app/actions/adminReserve.ts` ← 完了時にスタンプカウンター更新処理を追加
  - `src/app/actions/line-marketing.ts` ← スタンプ達成時のLINE送信処理
  - `src/app/admin/settings/edit/page.tsx` ← 特典設定UI
  - `src/app/admin/counter/page.tsx` ← 残スタンプバッジ表示
- **Supabase**: `patient_stamp_cards` テーブル（patient_id, clinic_id, stamp_count, last_stamp_at）新規追加
- **難易度**: 中（LINE Flex Messageのスタンプ画像実装が少し手間）

**優先度: 高** — 患者離脱防止と受付の自然な会話トリガーを同時に解決。競合の接骨院はほぼ未実装で差別化になる。

## 提案 2：来院前デジタル問診票 QR 送付（初診・長期ぶり来院に自動送信）

**観点**: ①利用者（受付・院長）が使いやすくなる

### 背景・きっかけ

整骨院のデジタル問診票は「iPad で待合室入力」が主流だが、NECや「リピクル」などの先行事例では**来院前にWebリンクを送って記入させる**方式への移行が進んでいる。  
参照: https://jpn.nec.com/medical_healthcare/monshin/index.html

Boxil掲載の比較記事（2024年）では「Web問診→電子カルテ自動連携」が受付時間を平均5〜10分短縮するとされており、1日30人院なら**毎日2〜5時間の受付工数削減**になり得る。  
参照: https://boxil.jp/mag/a9941/

現在のV-ARCには `questionnaire` Server Action があるが、患者側からのアクセスは受付中に限られており、**予約確定後に自動でリンクを送る**フローが存在しない。

### 提案内容

以下の2条件で患者にLINEで問診URLを自動送信する。

**条件A**: 初診（来院回数 0）の予約が確定した時点  
**条件B**: 前回来院から90日以上空いての予約（長期ぶり）

**メッセージ例**:
```
○○接骨院 予約確認 & 問診票のお願い

📅 予約日時: 11月20日（木）14:00
⏱ ご来院の3時間前までにご記入ください

問診票はこちら → [v-arc問診URL?patient=xxx&token=yyy]

ご記入後はそのまま来院ください。
当日の受付時間が短縮されます。
```

- 問診内容: 主訴・痛みの程度（スケール1〜10）・発症時期・既往歴・保険証情報（撮影アップロードも可能にする）
- 回答データは顧客詳細ページに自動連携、カウンター画面で「問診提出済み ✓」バッジ表示
- 未回答の場合は来院当日朝9時にリマインド送信

### 期待できる効果

- 受付での問診記入・説明時間が短縮 → 患者待ち時間が減少 → 満足度向上
- 保険証情報の事前確認で「確認漏れ」防止（前PRでシフト申し送りのテーマにも上がっていた課題）
- 初診の患者に「丁寧な院」という第一印象を与える

### 実装イメージ

- **関連ファイル**:
  - `src/app/actions/adminReserve.ts` ← 予約確定フック
  - `src/app/actions/questionnaire.ts` ← 既存の問診ロジックをWeb完結フォームに拡張
  - `src/app/actions/reminders.ts` ← 未回答リマインド送信
  - `src/app/admin/counter/page.tsx` ← 「問診提出済み」バッジ
- **Supabase**: `questionnaire_submissions` テーブルに `submitted_before_visit` フラグ追加、URLトークン管理カラム追加
- **難易度**: 中（URLトークン認証の設計と保険証アップロードを外すと「小」）

**優先度: 高** — 受付スタッフの負担を直接減らし、ミスも防ぐ。初診体験の質向上で口コミにも繋がる。

## 提案 3：時間帯別稼働ヒートマップ（予約密度カレンダーグリッド）

**観点**: ②データ分析・経営判断がしやすくなる / ①利用者（受付・院長）が使いやすくなる

### 背景・きっかけ

美容業界のDX事例（Aurant Technologies, 2026年）では、BigQueryやLooker Studioを使って「予約データからピーク時間帯を可視化する経営ダッシュボード構築」が推奨されている。これを外部ツール不要でV-ARC内に内製する提案。  
参照: https://aurant-technologies.com/blog/beauty-salon-dx-cluster-2026/

整体院CRMの比較記事（tol-app.jp）でも「予約優先制にした際の空き枠・稼働率管理」が導入判断の重要指標とされている。  
参照: https://tol-app.jp/columns/1806

現在の `analytics` ページには「曜日別来院数」BarChart が存在するが、**時間帯×曜日の2次元**での密度表示はなく、「月曜14時が毎週ガラガラ」「土曜10時に集中しすぎている」といったパターンが一目でわからない。

### 提案内容

分析ページに **「時間帯稼働マップ」タブ**を追加する。

- 表示形式: 7列（月〜日）×時間帯行（例: 09時〜20時）のグリッド
- セル色: 来院0人=白 → 来院最大=濃い緑（例: 5段階）
- 集計期間: 過去4週間 / 過去3ヶ月 を切り替え可
- ホバー表示: 「この時間帯 平均○人、最大○人、稼働率○%」
- 「空き枠推奨」機能: 一番空いている時間帯をハイライト表示 → キャンペーン予約枠に設定するなどのアクションにつなげる

**活用シーン例**:
- 「水曜午後がずっと空いている → そこに割引キャンペーン枠を設ける」
- 「土曜10時が毎週満員 → もう1枠増設 or 受付スタッフを2名体制に」
- 「スタッフシフト設計の根拠データとして使う」

### 期待できる効果

- 予約枠の設計を感覚ではなくデータで行える
- スタッフの過不足をシフト前に把握 → 残業・手待ちコスト削減
- 空き枠をキャンペーン活用することで売上の谷を埋められる

### 実装イメージ

- **関連ファイル**:
  - `src/app/admin/analytics/page.tsx` ← タブ追加
  - `src/app/actions/analytics.ts` ← `getHeatmapData(clinicId, range)` 関数追加（start_time 集計）
  - recharts の Cell/Heatmap は既存の `PieChart` 等の流れで実装可能（または純粋なCSS Gridでも可）
- **難易度**: 小〜中（集計クエリは比較的シンプル、ビジュアライズに少し工夫が必要）

**優先度: 中** — 経営判断の質を上げる。シフト設計との連携まで実現できると特に強力。

参照: https://resources.rework.com/ja/libraries/beauty-center-growth/data-driven-decisions-salon-owners

現在のカウンター画面には `last_visit_days`（前回来院からの日数）が内部で保持されているが、**受付スタッフへの"声かけヒント"としては表面化されていない**。AI秘書（`ai-secretary.ts`）も存在するが、管理者向けのコメント生成が主用途。

**ルールベース（即実装可能）の例**:

| 来院4回目 かつ 次回予約なし | 💬 継続提案のタイミング。コース説明を添えて次回予約を |
| 前回来院から60日以上 | 🔁 久しぶり来院。体調変化を丁寧に確認して |
| スタンプカード残り1 | 🎉 次回で特典達成！今日来院後に伝えてあげると喜ばれます |
| キャンセル待ちから来院 | ⏱ キャンセル待ちでの来院。対応に感謝の一言を |

- AI拡張（将来）: 施術メモ・問診履歴をAI秘書に渡して「今日注意すべき点」をAI生成
- スタッフがヒントを「参考にした」「スキップ」できるフィードバックボタンを追加 → 精度改善データに

### 期待できる効果

- 経験の少ないスタッフでも適切な接客ができる → スタッフの自己効力感UP
- 次回予約への自然な誘導 → 予約率向上
- 患者が「気にかけてもらっている」と感じる → 継続率向上

## 提案 5：複数院横断 KPI 比較ビュー（院長専用ダッシュボードタブ）

**観点**: ②データ分析・経営判断がしやすくなる

### 背景・きっかけ

Vercel + Looker Studio等を用いた「複数店舗横断ダッシュボード」の構築事例が美容サロン業界で広がっており（Aurant Technologies, 2026）、**「どの院が今月伸びているか・ボトルネックはどこか」を一画面で判断できる仕組み**が多院経営の必須ツールになりつつある。  
参照: https://aurant-technologies.com/blog/beauty-salon-dx-cluster-2026/

Zenotiの院長向け機能紹介では「ロケーション横断のKPIサマリー表示」が導入決定理由の上位に挙げられている。  
参照: https://grow.zenoti.com/blogs/are-you-tracking-the-right-kpis-for-salon-success

V-ARCはボール接骨院・からだ・マッスル・RELAQ等の複数院で共通利用されているが、**現在の分析・経営評価ページは院ごとの単独ビューのみ**。ぼーるくんが全院を俯瞰で見る画面がなく、院ごとに切り替えて比較する必要がある。

### 提案内容

分析ページ（または経営評価ページ）に **「院比較」タブ**を追加する（閲覧権限: 院長ロールのみ）。

**表示内容**（今月・先月・前年同月の3列）:

| KPI | ボール | からだ | マッスル | RELAQ |
|---|---|---|---|---|
| 月次売上 | ¥XXX,XXX | ¥XXX,XXX | ... | ... |
| 来院件数 | 〇件 | 〇件 | ... | ... |
| 新患数 | 〇人 | 〇人 | ... | ... |
| 自費比率 | ○% | ○% | ... | ... |
| 平均単価 | ¥X,XXX | ¥X,XXX | ... | ... |

- 各セルに「前月比 ▲〇%」の差分バッジ
- グラフ表示: 折れ線（全院の売上推移を重ね合わせ）
- AI秘書ボタン: 「今月の院間格差コメントを生成」（例:「RELAQが先月比+15%。マッスルは新患が減少傾向。」）
- 院ごとに「詳細を開く」で単院ビューへ遷移

### 期待できる効果

- 院ごとを手動で切り替える手間をゼロに → 月次経営会議の準備時間が大幅短縮
- 「RELAQだけ新患が少ない」「からだは自費比率が低い」等の気づきが瞬時に得られる
- スタッフへのフィードバック根拠（院間比較データ）を持てる

### 実装イメージ

- **関連ファイル**:
  - `src/app/admin/analytics/page.tsx` ← タブ追加
  - `src/app/actions/analytics.ts` ← `getMultiClinicSummary()` 追加（clinic_id パラメータを外す / 全院データ集計）
  - `src/app/actions/auth.ts` ← 院長ロール判定は既存を使用
  - `src/app/actions/ai-secretary.ts` ← AI院間コメント生成
- **難易度**: 中（clinic_id スコープを外した集計クエリ設計がポイント。RLSの見直しが必要な場合あり）

**優先度: 中** — ぼーるくんの経営判断を直接強化する機能。複数院規模になった今が実装のベストタイミング。
