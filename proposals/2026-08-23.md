# V-ARC 週次改善提案 — 2026-08-23

## 今週の要約（3行）

キャンセル後の枠を無駄にしない「待機リスト自動繰り上げ通知」を最優先提案する。失客直前の患者を受付画面で即座に把握できるアラートバッジも高優先。スタッフの定着率向上を狙い、週次パルスチェックインと施術者別リピート率ビューの追加で、数字とメンタルの両面を同時に強化する。

---

## 提案 1：キャンセル発生 → 待機患者へ自動 LINE 即時通知

**観点：** ①（受付が楽になる） ＋ ②（埋まらない枠ロスが経営数字に見える）

**背景・きっかけ**
Square Appointments の待機リスト機能解説（https://squareup.com/jp/ja/townsquare/wait-list-management）によると、キャンセルが発生した瞬間に「枠が空きました」通知をウェイティングの患者へ自動送信し、最初に反応した人が自動確定する仕組みが標準化されつつある。現システムにも `waitlist` ページ（`src/app/admin/waitlist/page.tsx`）とウェイティング登録機能（`createWaitlistEntryByStaff`）は存在するが、キャンセル発生時の自動 LINE 通知は実装されていない。受付が手動で電話・LINE をしており、連絡している間に次の患者への対応が滞る。

**提案内容**
- 予約が `cancelled` ステータスになった瞬間（`manage-reservation.ts` の cancel 処理直後）に、同日同時刻の待機リスト先頭の患者へ自動で LINE プッシュ通知を送る。
- メッセージ例：「【ボール接骨院】本日 14:00 の枠にキャンセルが出ました。ご希望の方は ○○ 時間以内にお知らせください。」
- 受信から X 分以内に返信がなければ、次順位へ自動エスカレーション。
- 通知ログを待機リスト画面に追記し、「通知済み・返答待ち・決定済み」のステータスを受付が確認できる。

**期待できる効果**
- 当日キャンセルによる空き枠消滅が激減 → 売上機会損失を直接防止。
- 受付の電話対応工数を削減（1 件あたり 5〜10 分の削減見込み）。
- 患者側の「空いたら連絡ほしい」ニーズに応え、満足度向上。

**実装イメージ**
- 関連ファイル：`src/app/actions/manage-reservation.ts`（cancel 処理末尾）、`src/app/actions/adminReserve.ts`（waitlist 取得）、`src/lib/line-links.ts`（LINE push）、`src/app/admin/waitlist/page.tsx`（ステータス表示追加）
- 難易度：**中**（既存 LINE push インフラ・待機リストテーブルを再利用できるため、新規 DB テーブルは通知ログ 1 本追加のみ）
- エスカレーション時刻はクリニック設定画面（`src/app/admin/settings/`）から変更できるとベスト。

**優先度：高**
キャンセルは毎日発生し、1 件の枠ロスは直接売上に響く。インフラが揃っているため工数対効果が最高。

## 提案 2：受付カウンターへの「失客予兆バッジ」リアルタイム表示

**観点：** ① ＋ ②

**背景・きっかけ**
治療院業界の顧客管理トレンド（https://chiryoin-hub.com/blog/osteopathic-clinic-customer-management）では「前回来院から 30 日経過 ＋ 次回予約なし」を失客予兆として自動検知し、スタッフへアラートを出す機能が 2026 年のスタンダードになりつつある。現システムの LINE キャンペーン（`line-campaign.ts`）には `minDaysSinceVisit` フィルターがあるが、**管理者が能動的にキャンペーン画面を開かないと分からない**。受付が毎朝カウンターを開いた瞬間に「今日の注意患者数」が目に入る設計になっていない。

**提案内容**
- カウンターページ（`src/app/admin/counter/page.tsx`）のヘッダー付近に「⚠ 30 日以上未来院（次回予約なし）◯人」バッジを追加。
- クリックすると、該当患者の一覧（氏名・最終来院日・経過日数・LINE 有無）がサイドパネルに展開。
- 「この患者にリマインドを送る」ボタン 1 つで、`sendLineCampaign` の既存処理を呼び出し個別 LINE 送信。
- 日数閾値（30 日・60 日・90 日）はクリニック設定で変更可能に。

**期待できる効果**
- 受付スタッフが能動的なリマインドを習慣化できる。
- 「気づいたときには手遅れ」を防止し、失客率の低下が期待できる（業界平均で 15〜25% のリピート率向上事例あり、出典：https://uravation.com/media/seitai-clinic-ai-guide-2026/）。
- 院長が都度 LINE キャンペーン画面を確認しなくても現場が動ける。

**実装イメージ**
- 関連ファイル：`src/app/admin/counter/page.tsx`（バッジ追加）、`src/app/actions/line-campaign.ts`（`collectTargets` ロジック再利用）、`src/app/actions/analytics.ts`（カウント取得用の軽量クエリを追加）
- 難易度：**小〜中**（カウント取得は既存 SQL ロジックの集計クエリを追加するだけ。サイドパネルは既存 UI コンポーネント流用）
- バッジは SSR で初期値を持ち、Supabase Realtime でリアルタイム更新するとなお良い。

**優先度：高**
実装が比較的軽く、毎日の受付業務に直結するため即効性が高い。

## 提案 3：施術者別リピート率ビュー（経営評価画面への追加タブ）

**観点：** ② ＋ ③

**背景・きっかけ**
美容室の経営 KPI 研究（https://haward-joyman.com/beauty/）では、「スタッフ別リピート率」が経営分析の最重要指標として挙げられている。リピート率の高い施術者は患者満足度が高く、低い施術者には接客・技術フォローが必要というシグナルになる。現システムの Analytics 画面は院全体の来院数・売上の前月比などはあるが、**誰が担当した患者がリピートしているか** は可視化されていない。リーダーボードはアクションポイント数のランキングであり、患者リピートという成果指標とは異なる。

**提案内容**
- 経営評価画面（`src/app/admin/evaluation/page.tsx`）または Analytics 画面に「スタッフ分析」タブを追加。
- 各施術者について以下を表示：
  - 担当予約件数（当月）
  - 担当患者のうち翌月以降に再来院した割合（リピート率）
  - 平均来院間隔（担当患者）
  - 前月比リピート率の矢印インジケーター
- 院長のみが閲覧できるロール制限を付ける（staff は自分のみ閲覧）。
- AI コメント機能（`generateAnalyticsComment`）への入力に施術者別リピート率を含めることで、「A さんの担当患者のリピート率が先月比 8% 低下しています。1on1 でフォローを検討してください」といった院長向け助言を生成。

**期待できる効果**
- 「感覚」ではなく「数字」でスタッフ育成の方針を立てられる。
- 院長が次月の研修・シフト配置を根拠をもって決定できる。
- リピート率が高い施術者が適切に評価され、モチベーション向上。

**実装イメージ**
- 関連ファイル：`src/app/actions/analytics.ts`（新関数 `getStaffRepeatRate` 追加）、`src/app/admin/evaluation/page.tsx` または `src/app/admin/analytics/page.tsx`（タブ追加）、`src/app/actions/ai-secretary.ts`（`generateAnalyticsComment` の入力拡張）
- 難易度：**中**（appointments テーブルを staff_id ＋ customer_id でグループ化して翌来院を追う SQL が必要。 インデックスとデータ量に注意）
- 難易度上げ要因：「リピート率の定義」（30 日以内再来院か、翌月中か）を院長と要件確認必要。

**優先度：中〜高**
スタッフ育成と経営判断の両方に使えるが、SQL 設計に若干時間がかかる。月次レポートに組み込むと即実用的。

## 提案 4：スタッフ週次パルスチェックイン（コンディション自己申告 + 院長向け集計）

**観点：** ③

**背景・きっかけ**
2026 年の離職防止・HR DX トレンドとして、週次パルスサーベイ（短い体調・モチベーション確認）が急速に普及している（https://chordone.jp/media/engagement/pulse-survey-tools-comparison.html、https://buzzkuri.com/columns/engagement/8333/）。医療・サロン業界では特に「スタッフの不調が患者対応の質低下→リピート率低下」の連鎖が問題になっており、早期検知が重要とされる。現システムにスタッフのコンディション把握機能は存在しない。

**提案内容**
- 毎週月曜（または任意設定日）にスタッフのシフトリマインド通知（`src/app/admin/shift-reminders/`）とセットで「今週のコンディションは？」を LINE または管理画面内プッシュで 5 段階アンケート送信。
- 回答は 1 タップ（⭐️×5 段階）で完了。任意でフリーコメントを添付可能。
- 院長向け画面（`settings/staff-schedule` か新規ページ）に週次チャートで集計を表示。
  - スタッフ別のコンディション推移グラフ
  - 3 週連続で ★2 以下のスタッフには自動フラグ（「1on1 推奨」バナー）
- スタッフ本人は自分のスコア履歴のみ閲覧可（他者のスコアは非表示）。

**期待できる効果**
- 月 1 面談では見逃しやすい「突然の退職・バーンアウト」を週次で早期検知できる。
- 院長・スタッフ双方が「コンディションを言語化する文化」を構築できる。
- パルスサーベイ導入で離職率 20〜30% 低下の事例あり（出典：SmartHR 社調査）。

**実装イメージ**
- 関連ファイル：`src/app/actions/shift-reminders.ts`（パルス送信処理を追加）、新規 DB テーブル `staff_pulse_entries`（staff_id, score, comment, week_start）、`src/app/admin/settings/staff-schedule/` に「パルス集計」タブ追加
- 難易度：**中**（LINE push は既存インフラ流用。新規テーブルとチャート UI が必要）
- Cron（週次）トリガーは Supabase Edge Function または Next.js の route handler + Vercel Cron で実装。

**優先度：中**
即効性はないが、離職防止は採用コスト削減に直結するため中長期 ROI が高い。

## 提案 5：来院マイルストーン自動 LINE（10回・30回・50回記念メッセージ）

**観点：** ① ＋ ③（患者と担当スタッフを同時に称える）

**背景・きっかけ**
海外の予約 SaaS（SimplyBook.me 等：https://simplybook.me/ja/faq）や国内サロン CRM（カロネード：https://service.kalonade.com/blog/salon-crm-customer-management-2025）では、「来院回数マイルストーン」で自動お祝いメッセージを送る機能が定番化している。現 LINE キャンペーンは手動一括送信であり、特定患者が N 回目を迎えたタイミングでの自動個別送信機能はない。`line-campaign.ts` の `collectTargets` に `minVisitCount` フィルターはあるが**イベントトリガー型**ではない。

**提案内容**
- 予約ステータスが「完了（来院済み）」になった際に、その患者の来院回数（来院日数ベースで算出、既存ロジックと同じ）が 10・30・50・100 回のいずれかに達したら自動 LINE を送信。
- メッセージ例：「{name} さん、ボール接骨院へのご来院 30 回目おめでとうございます！いつもご愛顧いただき、ありがとうございます。次回ご来院時に小さなプレゼントをご用意しています 🎉」
- 院長が設定画面からマイルストーン回数とメッセージテンプレートを編集可能。
- 受付カウンター画面に「今日のマイルストーン達成予定患者」バッジを表示し、スタッフが声をかけるきっかけを作る（提案 2 のバッジと同じ UI パターンで追加）。

**期待できる効果**
- 患者の「継続してよかった」感を強化し、長期リピート率が向上。
- スタッフが「お祝いの声かけ」をしやすくなり、コミュニケーションが活性化。
- 口コミ・紹介促進のきっかけとなる（「10 回達成でお祝いがある院」として SNS 投稿を誘発）。

**実装イメージ**
- 関連ファイル：`src/app/actions/manage-reservation.ts`（完了ステータス変更処理の末尾に来院回数チェックを追加）、`src/app/actions/line-campaign.ts`（個別送信関数を追加）、`src/app/admin/settings/page.tsx`（マイルストーン設定 UI）
- 難易度：**小〜中**（来院回数カウントロジックは `collectTargets` 内で既に実装済み。イベントトリガー呼び出しを追加するだけ）
- 注意：同日に複数予約がある場合のカウント二重防止処理は、既存の「日単位カウント」ロジックを踏襲する。

**優先度：中**
実装コストが低い割にブランド体験向上効果が大きい。提案 1・2 の完成後に着手しやすい。

## 提案 6：受付カウンターへの「本日の稼働率」リアルタイムゲージ

**観点：** ① ＋ ②

**背景・きっかけ**
ホットペッパービューティーのサロン向け経営ガイド（https://pro.estheticfan.jp/guide/management/）では「稼働率（席・スタッフ利用率）のリアルタイム把握」が売上最大化の基本 KPI として挙げられている。現カウンター画面には本日の予約リストは見えるが、**稼働率（今日の枠の何%が埋まっているか）** がワンクリックで確認できる場所がない。院長・受付が「あと何枠空いている」を直感的につかめると、飛び込み患者への案内や当日の増枠判断が即座にできる。

**提案内容**
- カウンターページ上部（または予約一覧ページ）に本日の稼働率ゲージを追加：
  - 「本日 予約 12 / 最大受入 16 枠（稼働率 75%）」と数値とプログレスバーで表示
  - 残り枠 → 緑、75% 超 → 黄、90% 超 → 赤のカラーコーディング
  - キャンセル・ノーショーも差し引いた「実来院稼働率」をリアルタイムで反映
- 「最大受入枠数」は `settings/staff-schedule` で設定済みの情報から自動算出。
- 院長ダッシュボード（`src/app/admin/dashboard/`）の日次サマリーに稼働率カードを追加し、過去 7 日の推移を表示。

**期待できる効果**
- 受付が「今日は余裕がある」を即判断 → 飛び込み・当日予約の積極的な受け入れ。
- 院長が夕方に稼働率を見て「明日の空き枠を SNS に投稿する」などの即断ができる。
- 週次・月次の稼働率トレンドが経営評価データとして蓄積される。

**実装イメージ**
- 関連ファイル：`src/app/admin/counter/page.tsx`（ゲージ UI 追加）、`src/app/admin/dashboard/DashboardClient.tsx`（稼働率カード追加）、`src/app/actions/analytics.ts`（当日稼働率取得関数 `getTodayOccupancyRate` 追加）
- 難易度：**小**（appointments テーブルの当日レコードを集計するだけ。最大枠数は既存の clinic slots 情報から算出可能）
- Supabase Realtime を使えばキャンセルや追加予約を即時反映できる。

**優先度：中**
実装が最も軽い提案の一つ。カウンターと院長ダッシュボードに同時に価値を追加できる。
