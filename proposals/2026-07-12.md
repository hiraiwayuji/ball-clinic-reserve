# V-ARC 週次改善提案 — 2026-07-12

## 今週の要約（3行）

海外サロン管理SaaS（Zenoti・Square・Fresha）の最新機能と、接骨院向けCRM/KPI記事を横断調査。「AIが個別リスク予測をしてスタッフに次のアクションを示す」という設計が2026年のスタンダードになりつつある。既存の休眠アラートやリーダーボードをそのまま伸ばすのではなく、①AI多指標スコアリング・②スタッフ別再診率・③当日申し送り・④個人KPI・⑤空き枠予測LINEトリガーの5本で、V-ARCを「使えば使うほど現場が賢くなる」SaaSへ進化させる提案をまとめた。

---

## 提案 1 — AI離脱リスクスコア（顧客一覧 + カウンター統合表示）

**観点:** ① ②

### 背景・きっかけ

現在の「休眠患者アラート」は「30日以上来院なし」という単純な日数フラグ（`src/app/admin/customers/CustomersTable.tsx` L870〜）。Zenoti の2026年ベンチマークレポートによれば、AI を使ったリテンションキャンペーン実施院はリブッキング率が41% → 64% に改善しており、単純な"◯日空き"ではなく複数指標の組み合わせスコアで予測することが重要とされている。Express Analytics の事例でも、来院頻度変化 + キャンセル率 + 直近支払額の低下を組み合わせることでチャーン予測精度が大幅に向上すると報告されている。

参照:
- https://www.expressanalytics.com/blog/predict-customer-churn-retention-strategies
- https://www.zenoti.com/thecheckin/best-salon-booking-software (Zenoti 2026 Benchmark Report)

### 提案内容

**スコア計算ロジック（サーバー側）**

| 指標 | 重み |
|---|---|
| 過去3か月の来院間隔の延び率（例: 14日→21日→35日は加速中） | 高 |
| 過去6か月のキャンセル/ノーショー回数 | 中 |
| 直近来院から今日までの日数（絶対値） | 中 |
| 総来院回数（少ないほど定着していない） | 低 |

スコアを 1〜5 の整数で返し、4 以上を「要注目」、5 を「緊急」とする。

**UI変更点**

- 顧客一覧テーブルに「リスク」列を追加。🔴🟡🟢のバッジで一目判断。フィルター/ソート可。
- 受付カウンターの予約カード（`src/app/admin/counter/page.tsx`）に、そのお客さんのスコアが4以上の場合のみ「⚠ 離脱サイン」バッジと「次回予約を勧めてみて」というひと言ヒントを表示。受付スタッフが自然に声かけできる。

### 期待できる効果

- 「なんとなく来なくなった患者」への声かけタイミングが明確になり、受付スタッフが迷わない
- 院長が月初にリスクスコア上位20名を確認しLINEを打てる、という運用ルーチンが生まれる
- 既存の「休眠患者アラート」タブとの差別化: あちらは発生後の通知、こちらは予防的な介入

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/actions/analytics.ts` | `getChurnRiskScores(clinicId)` を追加。来院履歴 + キャンセル履歴からスコア計算 |
| `src/app/admin/customers/CustomersTable.tsx` | リスク列追加、フィルター追加 |
| `src/app/admin/counter/page.tsx` | 予約カードにバッジ追加（threshold=4） |

**難易度:** 中（Supabase のクエリ設計がポイント、Gemini 不要でルールベースでも可）

**優先度:** 高 — 既存の休眠アラートより予防効果が高く、受付スタッフの行動変容に直結するため。

## 提案 2 — スタッフ別「再診転換率」ダッシュボード（分析ページに新タブ）

**観点:** ② ③

### 背景・きっかけ

Square Appointments の「Team Performance Report」は、スタッフごとの予約件数・リブッキング率・キャンセル率をダッシュボードで表示する機能を持つ（2025年現在）。接骨院向けKPIの専門解説（info-ligua.jp）でも「指名件数」「リピート率（スタッフ別）」が経営の核心指標として挙げられているが、V-ARC の現アナリティクス（`src/app/admin/analytics/page.tsx`）にはスタッフ軸の再来院率が存在しない。リーダーボード（`src/app/admin/leaderboard/page.tsx`）はアクションポイントの合計順位であり、「このスタッフが施術した患者が翌月も来てくれる率」は別の価値指標。

参照:
- https://squareup.com/help/us/en/article/7904-square-appointments-reporting
- https://info-ligua.jp/column/kpi-setting.html

### 提案内容

分析ページ（`/admin/analytics`）に「スタッフ別」タブを追加し、以下を表示:

1. **再診転換率カード**（月ごと）: スタッフAが担当した患者のうち、翌月も1回以上来院した割合
2. **指名比率推移**（月グラフ）: そのスタッフを指名した予約 / 全予約
3. **担当別平均来院間隔**: 短いほどリテンション力が高い

カードは院長ビュー（全スタッフ横並び）とスタッフ本人ビュー（自分の推移のみ）で出し分ける（`role` チェック済みの既存認証を流用）。

### 期待できる効果

- 「A先生に施術してもらった患者の再診率が他より15%高い」という具体的なフィードバックが生まれる
- スタッフの接遇改善・指名制度導入の判断データとして即使える
- リーダーボードの「活動ポイント」とは補完関係になり、量と質の両方を評価できる体制に

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/actions/analytics.ts` | `getStaffRetentionMetrics(year, month)` を追加 |
| `src/app/admin/analytics/page.tsx` | 新タブ追加（Recharts の BarChart を流用） |

**難易度:** 中（Supabase で appointments テーブルを staff_id × 月で集計するクエリが核心）

**優先度:** 高 — 院長がスタッフ評価や指名制度の設計に使えるデータが今ゼロのため、経営判断インパクトが大きい。

## 提案 3 — 患者当日申し送りメモ（受付 ↔ 施術スタッフ リアルタイム）

**観点:** ①

### 背景・きっかけ

整骨院向けCRM比較記事（archrise-works.com）で「受付スタッフと先生の間でインカムを使わずに『この患者様は今日誕生日です』などの申し送りを画面上で共有できる機能が高評価」と報告されている。V-ARC には問診票機能（`src/app/admin/customers/QuestionnaireDialog.tsx`）はあるが、これは静的な患者情報であり、当日の「今日のシフト限定の引き継ぎ」には使えない。複数院 / 多スタッフ運用では、受付が把握した情報（「今日はお子さんの運動会帰り」「最近腰より肩が気になると話していた」）がそのまま施術スタッフに届かないケースが発生している。

参照:
- https://www.archrise-works.com/blog/webmarketing/整骨院向けcrmとは？患者管理・予約・再来院を効率化するおすすめツールを紹介

### 提案内容

受付カウンターの予約カード（`src/app/admin/counter/page.tsx`）に「今日の申し送り」入力欄（1〜2行）を追加。

- **書き込み**: 受付スタッフがチェックイン操作のついでに入力（任意）
- **表示場所**: カウンターページ + 予約一覧ページ（`/admin/appointments`）に小バッジで表示
- **自動消去**: 当日営業終了後（設定した閉院時刻 + 1時間）に自動削除
- **Supabase Realtime**: 書き込み後、同一クリニックIDを見ている他スタッフの画面にほぼリアルタイムで反映（既存の `realtimeGuard` パターンを流用）

**DBイメージ（新テーブル）:**
```sql
create table daily_patient_notes (
  id uuid primary key default gen_random_uuid(),
  clinic_id uuid not null,
  customer_id uuid not null references customers(id),
  note_date date not null,  -- 当日のみ有効
  content text not null,
  created_by uuid,
  created_at timestamptz default now()
);
-- note_date < today を自動削除する pg_cron ジョブ or RLS policy
```

### 期待できる効果

- スタッフ間のインカムや口頭伝達ミスが減り、患者満足度と施術品質が均質化する
- 誕生日の声かけ漏れ・痛みの変化の伝達漏れが可視化される
- 実装が小さい割に現場インパクトが大きく、スタッフから「使いやすい」と評価されやすい

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| Supabase migration | `daily_patient_notes` テーブル追加 |
| `src/app/actions/adminReserve.ts` | `upsertDailyNote(customerId, content)`, `getDailyNotes(date)` 追加 |
| `src/app/admin/counter/page.tsx` | 予約カードに申し送り入力欄追加 |
| `src/app/admin/appointments/page.tsx` | ノート有フラグのバッジ表示 |

**難易度:** 小〜中（Supabase Realtime は既存パターン流用）

**優先度:** 高 — 複数院展開・多スタッフ運用での差別化ポイント。実装コストが低く即効性が高い。

## 提案 4 — スタッフ個人KPIカード（月次目標 自己設定 + 進捗バー）

**観点:** ③

### 背景・きっかけ

既存のリーダーボードは「活動ポイント合計のランキング（今週の MVP）」であり、競争型の外発的モチベーション設計。一方、接骨院スタッフ育成研究（rehasaku.net, zenkoku-iryo.com）では「スタッフが自分でKPIを設定し、月次で振り返る1on1が定着率に直結する」と報告されている。OKR小規模チーム向け解説（kaonavi.jp）でも、個人OKRは「自分で決めたから達成したい」という内発的動機を生む設計が重要とされる。V-ARC には現在スタッフが「自分の今月の目標と進捗」を見る画面がなく、院長側の評価（`/admin/evaluation`）は院全体の目標であってスタッフ個人ものではない。

参照:
- https://rehasaku.net/media/education/3647/
- https://www.kaonavi.jp/dictionary/okr/
- https://info-ligua.jp/column/kpi-setting.html

### 提案内容

新ページ `/admin/my-kpi`（またはダッシュボードのウィジェット）で、各スタッフが毎月設定できる個人KPIカードを提供。

**設定できる指標（月初にスタッフ自身が入力）:**

| 指標 | 取得方法 |
|---|---|
| 月間担当施術件数 目標 | appointments テーブルの staff_id 集計で自動進捗 |
| 担当キャンセル0日数 目標（○日連続） | cancellation ログから算出 |
| 新規患者対応件数 目標 | is_first_visit フラグ集計 |
| 自由入力目標（例: 「腰痛ストレッチの説明回数○回」） | 自己報告チェックボックス |

**UI:**
- 各指標に進捗バー（例: 「施術件数 38/50件 76%」）
- 月末に「今月どうでしたか？」1行コメント入力 → 院長が閲覧可能（1on1 の事前資料になる）
- AI秘書による月中ひと言メッセージ（例:「先月より5件ペースが速いです！残り8件、ラストスパートを」）→ 既存の `generateStaffBriefing` を拡張

**院長ビュー:** 全スタッフのKPIサマリー一覧（`/admin/evaluation` または新タブ）

### 期待できる効果

- 「管理される」から「自分で決めて達成を目指す」構造に変わり、スタッフの主体性が上がる
- 院長の1on1や月次面談の話題が「データ」から始められ、面談の質が向上する
- リーダーボード（競争型）と個人KPI（自己成長型）の二軸でモチベーション設計が完成する

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| Supabase migration | `staff_personal_goals` テーブル追加 |
| `src/app/actions/analytics.ts` | `getMyKpiProgress(staffId, year, month)` 追加 |
| `src/app/admin/my-kpi/page.tsx` | 新規作成（個人KPIカード） |
| `src/app/actions/ai-secretary-multi.ts` | `generateStaffBriefing` に KPI 進捗コンテキスト追加 |

**難易度:** 中（新テーブル + 集計クエリ + 新ページ）

**優先度:** 中〜高 — スタッフ定着が経営課題である院では即効性あり。リーダーボードとセットで「評価体系」が整う。

## 提案 5 — 予約空き枠予測 × LINEキャンペーン自動トリガー

**観点:** ② ①

### 背景・きっかけ

SalonBoostの2026年AI自動化レポートでは「AIが過去の予約パターンから空き枠を予測し、空きになりやすい時間帯にターゲットを絞った告知を自動送信する」設計が紹介されている。Zenoti のデータでも「予測型キャンペーンを使う院はそうでない院より4倍の売上成長率」と報告（2025年ベンチマーク）。V-ARC には既に `getYearlyTrend`, `getWeekdayBreakdown` が実装されているが（`src/app/actions/analytics.ts`）、これらは過去の実績表示であり「来週この曜日が空きそうだから今日配信すべき」という予測→アクションの連携はない。LINE配信機能（`src/app/actions/line-marketing.ts`）も存在するが、配信のトリガーは手動。

参照:
- https://salonboost.online/blog/ai-automation-salon-management-2025
- https://www.zenoti.com/thecheckin/best-salon-booking-software
- https://lflow.net/column/line-sekkotsuin-marketing/

### 提案内容

**ステップ1: 空き枠予測スコアの計算（週次バッチ or オンデマンド）**

- 対象期間: 向こう2週間
- 計算方法: 過去8週間の同曜日・同時間帯の予約充填率の平均と標準偏差を算出し、現在の予約数が「平均 - 1σ」を下回る時間帯を「空き予測枠」と判定
- 結果は `slot_predictions` テーブルまたはメモリキャッシュに保存

**ステップ2: 経営評価ページ（`/admin/evaluation`）への警告バナー表示**

「来週の火曜 14〜16時が例年比 -35% の予約状況です。今日中にLINEキャンペーンを配信しますか？ →【配信ページへ】」という1クリックナビゲーション。

**ステップ3: LINE配信ページ（`/admin/marketing`）への連携**

提案バナーからワンクリックで飛べ、配信セグメントに「直近30日内に来院歴あり・来週の該当時間帯に予約なし」が自動選択された状態でページが開く。メッセージ文面はAIが生成（既存 `admin-marketing-actions.ts` のAI文面生成を流用）。

### 期待できる効果

- 空き枠をデータで発見し、LINE配信という既存アクションに接続することで稼働率改善ループが回り始める
- 院長が「なんとなくLINEを打つ」から「データ根拠のあるLINEを打つ」に変わる
- 月間稼働率 +5〜10% 改善で、受付・施術スタッフへの余裕も生まれる

### 実装イメージ

| 関係ファイル | 変更内容 |
|---|---|
| `src/app/actions/analytics.ts` | `getSlotFillPredictions(weeksAhead: number)` 追加 |
| `src/app/admin/evaluation/page.tsx` | 予測警告バナーコンポーネント追加 |
| `src/app/admin/marketing/page.tsx` | URL param でセグメントをプリセットする受け口追加 |
| `src/app/actions/line-marketing.ts` | セグメントフィルター拡張（時間帯 × 来院歴 × 予約なし） |

**難易度:** 大（予測ロジックの統計計算 + 3画面連携が必要。ただしAI/MLは不要でルールベース統計で十分）

**優先度:** 中（インパクトは最大級だが実装工数が大きいため、提案1〜3を先に着地させてから着手を推奨）
