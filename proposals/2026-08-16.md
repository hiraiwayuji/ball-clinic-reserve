# V-ARC 週次改善提案 — 2026-08-16

## 今週の要約（3行）

- **キャンセル空き枠の自動活用**と**休眠患者への自動LINE配信スケジュール化**で、受付の手間ゼロ・売上機会損失ゼロを同時に実現できる状態を目指す。
- 顧客一覧への**失客リスクバッジ**と**問診傾向ダッシュボード**を加えることで、院長が「次に誰を呼び戻すか・どんな治療ニーズが増えているか」をデータで即判断できるようになる。
- スタッフの**個人月次目標＋週次チェックイン**機能は、既存ポイントリーダーボードと組み合わせることで「競争」から「自己成長」へモチベーションの質を高め、離職防止にも直結する。

---

## 提案 1｜キャンセル待ち自動繰り上げ LINE 通知（スマートフィル）

**観点：① 利用者（受付）が使いやすくなる**

### 背景・きっかけ

湘南美容クリニック（SBC）は 2025 年 11 月に「MySBC 予約待ち機能」を追加。予約が満杯の場合でもキャンセル待ち登録できるようになり、空き発生時にプッシュ通知が届く仕組みを実装した（参照：[SBC 二子玉川院 超速報記事](https://www.s-b-c.net/clinic/branch/futakotamagawa/special/20251127_hp_cancel-reservation/)）。

海外では SimplyBook.me がキャンセル発生時に「当日のキャンセル待ち登録者へ自動メール」機能を持つ（参照：[SimplyBook.me Waiting List feature](https://help.simplybook.me/index.php/Waiting_List_custom_feature)）。

V-ARC の `waitlist/page.tsx` を確認すると、キャンセル待ちリストの手動管理はできるが、「予約がキャンセルされた瞬間に待ち 1 番の患者へ自動 LINE 通知」を送る仕組みがない。受付が空き枠に気づいてリストを見て電話する、というアナログ作業が残っている。

### 提案内容

`manage-reservation.ts` でキャンセル処理が完了した際に、同スロットの `waitlist` テーブルを `position` 順に検索し、LINE 連携済みの患者には LINE メッセージ、未連携なら内部通知（受付カウンターへのアラート）を自動送出する。

- **受付画面**：キャンセル完了モーダルに「キャンセル待ち 〇 名に通知しました」と表示
- **管理画面（waitlist/page）**：通知済み / 未通知 / 予約確定済みのステータスを列で追加
- **患者側**：LINE メッセージ「〇月〇日 〇時の枠が空きました。24 時間以内に予約ページよりご予約ください。→ [URL]」

### 期待できる効果

- キャンセル発生時の空き枠が自動で埋まり、1日あたり 1〜2 枠の機会損失を削減
- 受付スタッフの「キャンセル待ちリスト確認→電話」作業がゼロになる

### 実装イメージ

| ファイル | 変更内容 |
|---|---|
| `src/app/actions/manage-reservation.ts` | キャンセル完了後に `triggerWaitlistNotification(slotId)` を呼ぶ |
| `src/app/actions/line-marketing.ts` | `sendLineToCustomer(customerId, message)` の関数追加（既存 campaign API を流用） |
| `src/app/admin/waitlist/page.tsx` | 通知ステータス列・フィルターを追加 |
| Supabase DB | `waitlist` テーブルに `notified_at`, `status` カラム追加 |

**難易度：小〜中**（LINE API 連携は既存の campaign 機能で実績あり）

### 優先度：**高**

キャンセルは毎日発生する出来事で、空き枠の回収率が直接売上に影響する。既存の LINE 連携・waitlist インフラがあるため追加工数も少ない。

## 提案 2｜休眠患者 LINE 自動掘り起こしスケジューラー

**観点：① 使いやすくなる、② データ分析・経営判断**

### 背景・きっかけ

2026 年版整骨院・接骨院顧客管理ガイド（参照：[chiryoin-hub.com ブログ](https://chiryoin-hub.com/blog/osteopathic-clinic-customer-management)）では「前回来院から 30 日経過 ＋ 次回予約なし」の患者を自動抽出して掘り起こし配信するのが離反防止の定石とされている。

LINE 連携予約導入後にリピート率約 9 割を実現した事例も報告されている（参照：[rsvia.co.jp 整骨院LINE予約解説](https://rsvia.co.jp/column/osteopathi_line_reservations/)）。

V-ARC の `marketing/message` ページには `minDaysSinceVisit` フィルターでターゲット絞り込みをした上で LINE 配信する機能がある。しかし「毎週月曜 9 時に自動で 30 日未来院患者へ配信」というスケジューラーがなく、スタッフが毎週手動で開いて操作しなければならない。

### 提案内容

LINE メッセージページに「**定期配信スケジュール**」タブを追加：

1. 配信条件（例：最終来院 30 日以上・次回予約なし・女性 30〜50 代）を保存
2. 配信タイミング（毎週月曜 9:00 JST など）を設定
3. 配信文テンプレートを登録（AI 秘書で自動生成も可）
4. 設定後は cron / Supabase Edge Function が自動実行、配信履歴に自動記録

**管理画面には「スケジュール一覧」**（有効/停止 トグル、直近送信日時、送信人数）を表示。

### 期待できる効果

- 休眠患者の掘り起こしを「忘れずに毎週」実施できる → リピート来院率 10〜20 %向上（業界事例ベース）
- 配信作業の工数ゼロ化（月あたり 2〜3 時間の節約）
- 配信効果（開封・来院数）を自動で経営評価画面の指標に連携可能

### 実装イメージ

| ファイル | 変更内容 |
|---|---|
| `src/app/admin/marketing/message/page.tsx` | スケジュールタブを追加 |
| `src/app/actions/line-campaign.ts` | `saveSchedule` / `listSchedules` / `deleteSchedule` を追加 |
| Supabase DB | `line_campaign_schedules` テーブル（clinic_id, filters JSON, cron_expr, template, enabled） |
| Supabase Edge Function | cron トリガーで `getLineCampaignTargets` を呼び LINE 配信 |

**難易度：中**（Supabase Edge Function の cron 設定が必要。LINE 配信ロジック自体は既存流用）

### 優先度：**高**

接骨院経営で最大の課題は「来なくなった患者の掘り起こし」。手動運用のままでは継続できない。自動化の恩恵が毎週永続的に発生する。

## 提案 3｜患者 LTV スコア＋失客リスクバッジ（顧客一覧拡張）

**観点：② データ分析・経営判断がしやすくなる**

### 背景・きっかけ

美容クリニック向け LTV 向上戦略の調査（参照：[アイラボ LTV 向上記事 2025](https://ilabs.jp/2025/08/ltv/)）では「新患獲得コストは既存患者維持の 5〜7 倍かかる」ことが指摘されており、患者の LTV を可視化して優先的にフォローする仕組みが重要とされている。

march（医療集患 SaaS）の事例では LINE と CRM 連携で再診率 2 倍を達成（参照：[march-cos.com CRM ガイド 2025](https://march-cos.com/2025/06/26/clinic-crm-guide/)）。

V-ARC の顧客管理画面（`customers/page.tsx`）はリスト表示のみで、「この患者はいつ来なくなりそうか」「長期的に収益に貢献している患者は誰か」の一目把握ができない。

### 提案内容

顧客一覧テーブルに 3 つの指標を追加：

1. **LTV スコア**（総支払額 / 来院回数 × 来院継続月数の簡易スコア）— 高・中・低バッジ
2. **失客リスク**（最終来院日からの経過日数 ＋ 次回予約有無で算出）
   - 🔴 高リスク：30 日以上来院なし ＋ 次回予約なし
   - 🟡 中リスク：21 日以上来院なし
   - ⚪ 正常
3. **継続月数**（初回来院からの経過月数）

フィルターも追加：「失客リスク高のみ表示」「LTV 高の患者のみ」など。

院長は毎朝このリストを開くだけで「今日誰にアプローチすべきか」が分かる。

### 期待できる効果

- 失客リスクの高い患者を早期発見し、提案 2 の LINE 配信に即連携できる
- 院長の「経営直感」に代わるデータ根拠が生まれ、施策の精度が上がる
- LTV 高患者の傾向（年代・治療内容・来院頻度）が分かり、新患獲得の打ち手に活かせる

### 実装イメージ

| ファイル | 変更内容 |
|---|---|
| `src/app/actions/adminCustomers.ts` | `getCustomers` に LTV・リスクスコアの計算ロジックを追加（sales, appointments テーブルを JOIN） |
| `src/app/admin/customers/CustomersTable.tsx` | バッジカラム・フィルターUI を追加 |

**難易度：中**（SQL の JOIN は既存インフラで可能。スコア計算ロジックのビジネスルール定義が鍵）

### 優先度：**中**

データは既に Supabase にある。表示するだけなので UI 変更は軽量。ただし「スコアのルール定義」をぼーるくんと合意する必要がある。

## 提案 4｜問診データ傾向ダッシュボード（症状・年代・性別クロス集計）

**観点：② データ分析・経営判断がしやすくなる**

### 背景・きっかけ

問診票のデジタル化と集計分析は 2026 年の接骨院 DX の最前線（参照：[RIPCLE 問診デジタル化メリット解説](https://ripicle.com/osteopath/column/1351/)、[カルッテ 電子カルテ連携](https://kartie-cloud.jp/media/120/)）。問診データを集計することで「腰痛 vs 肩こり vs スポーツ外傷」の患者構成比・季節変動・年代別の悩み傾向が分かり、治療メニュー展開や広告戦略に直結する。

V-ARC には `questionnaire` テーブル ＋ `src/app/admin/customers/QuestionnaireDialog.tsx` で問診票を記録しているが、**集計・可視化する画面が存在しない**。データはあるが「宝の持ち腐れ」状態。

### 提案内容

`/admin/analytics` の新しいタブ（または `analytics/questionnaire/page.tsx` として独立ページ）で以下を表示：

1. **主訴 TOP 10 バーグラフ**（腰痛・肩こり・膝痛・スポーツ外傷…etc の患者数）
2. **年代×主訴クロス表**（20 代は肩こり、40〜50 代は腰痛 など可視化）
3. **月別症状トレンド折れ線**（夏は熱中症・水分不足系、冬は腰痛悪化 など季節性を確認）
4. **初診時主訴 vs 継続来院患者の主訴比較**（どんな悩みの患者がリピートするか）

画面右上に「AI がこの傾向からメニュー提案を出す」ボタン（既存 AI 秘書機能を転用）。

### 期待できる効果

- 「今の患者層に刺さる SNS 投稿ネタ」が明確になる（例：40 代腰痛が多い → 腰痛施術事例を重点投稿）
- 季節に合わせた治療メニュー開発の根拠が得られる
- 複数院展開時に「院ごとの患者属性の違い」を比較できる

### 実装イメージ

| ファイル | 変更内容 |
|---|---|
| `src/app/actions/analytics.ts` | `getQuestionnaireTrends()` 関数を追加（questionnaire テーブルを GROUP BY 集計） |
| `src/app/admin/analytics/page.tsx` | 「問診傾向」タブを追加、Recharts でグラフ描画 |

**難易度：中**（Recharts は既存 analytics ページで使用済み。questionnaire テーブルのスキーマ確認が必要）

### 優先度：**中**

問診データが溜まっているほど価値が高まる。患者数が増えた今が導入タイミング。SNS 投稿との連携で集客改善に直結する「経営の眼」になる。

## 提案 5｜スタッフ個人月次目標＋週次セルフチェックイン

**観点：③ スタッフ管理がしやすく、モチベーションが上がる**

### 背景・きっかけ

クラウド 1on1 ツール **TeamUp** の導入事例（参照：[TeamUp 利用事例](https://www.teamup.jp/interviews/dsjit)）では「現場スタッフが 1on1 を通して自発的に動くチームになる」効果が報告されており、週次振り返りで「数値結果・実行した行動・障害を分けて確認する」ことが個人成長に不可欠とされている。

美容サロンスタッフ育成研究（参照：[KUROCO サロンスタッフ育成術](https://kuroco.team/blog-business-salonikuseijutsu/)）では、「理念・ビジョンの共有不足」が離職・モチベーション低下の主因であり、スタッフが「自分が何に向かっているか」を毎週確認できる場が必要とされている。

V-ARC の `leaderboard/page.tsx` はポイントランキングで「競争」を促す仕組みだが、「スタッフ本人が先月立てた目標を今週どこまで達成したか」を振り返る機能がない。外発的動機（ランキング）から内発的動機（目標達成感）へのステップが抜けている。

### 提案内容

`/admin/my-schedule` ページ（既存のスタッフ個人ページ）に「**目標・振り返り**」タブを追加：

**月初（目標設定）：**
- スタッフ本人が「今月の施術件数目標・売上貢献目標・習得したい技術」を 3 項目まで入力
- 院長が「コメント＋承認」できる（承認するとリーダーボードの今月バッジに反映）

**毎週月曜（週次チェックイン）：**
- 先週の行動を 3 段階で自己評価（できた / 半分できた / できなかった）
- 「一言振り返り」を自由入力（50 文字以内）
- チェックインすると +3pt（リーダーボードと連動）

**月末（振り返り）：**
- 月目標達成率を自動計算（ポイント・施術件数ベース）
- 院長がコメントを残す → スタッフに通知

### 期待できる効果

- スタッフが「自分が評価されている」「成長が見えている」と感じ、離職率低下
- 院長と各スタッフの 1on1 が「チェックイン記録を見ながら話す」形になり、面談準備工数が減る
- 月次目標 × ポイント達成率で、来月の研修・勉強会テーマを院長がデータ基準で選べる

### 実装イメージ

| ファイル | 変更内容 |
|---|---|
| `src/app/admin/my-schedule/page.tsx` | 「目標・振り返り」タブを追加 |
| `src/app/actions/evaluation.ts` | `saveStaffGoal` / `saveWeeklyCheckin` / `getStaffGoalHistory` を追加 |
| `src/app/actions/security.ts` | チェックイン完了時にポイント +3 を付与するロジックを追加 |
| Supabase DB | `staff_goals`（月次目標）、`staff_checkins`（週次振り返り）テーブルを追加 |
| `src/app/admin/leaderboard/page.tsx` | 「目標設定済み」バッジをランキング行に表示 |

**難易度：中**（複数テーブル追加・UI は既存コンポーネントで構成可能）

### 優先度：**中〜高**

スタッフ定着は接骨院経営の中長期課題。リーダーボードとのシナジーが高く、実装後は毎週自動的に使われる継続的価値がある。複数院展開でスタッフ人数が増えるほど効果が増大。
